01 / 新闻与社区

从托管产品到公开权重，发布速度快于部署成熟度

Jev 把快速、结构化、可报告概率的判断推到产品前台；社区随后出现独立训练实现与精度变体。时间线说明公开产物快速增加，不证明几天内完整复现了原厂研发。必须分开看产品能力、算法证据、权重格式和可运行服务。[1][37][45]

新闻是研究入口；具体能力仍要回到接口、源码与评测条件。

  1. 1
    2026-09-15 · Jev 发布

    TypeSafe 开放早期访问，提供结构化判断与概率的托管 API；官方完整结构和 RLCD 训练配方未在本次核查资料中披露。[1][22]

  2. 2
    2026-09-17 · NanoJev 仓库创建

    TianyuCodings 提供 Qwen3-0.6B 决策头实现、训练流水线和权重。仓库创建日期不等于研发只用了两天，也不证明与 Jev 能力相等。[37][41]

  3. 3
    2026-09-18 · MLX 4-bit 变体创建

    ZeroDegress 发布 NanoJev 根检查点的量化权重。它是存储精度变体，不是另训的新模型；其仓库明确只发权重，未附 MLX 决策运行时。[45][46]

可执行代码越来越多，选型仍取决于你要自动化哪种判断。

问题验收标准
输出是否有界？能列出候选、等级或判断命题，包含不适用 / 信息不足路径。
是否可供代码组合？区分语义判断、精确计算、权限和执行；模型不会自动承担整个工作流。
发布物是否真能运行？文件完整、加载兼容、决策接口正确、业务质量达标须分别验证。

02 / 产品定位

结构化决策模型把语义判断变成软件可消费的结果

本文把以预定义判断及概率为主要接口、供软件直接使用的模型称为「结构化决策模型」；这是研究口径，不是统一行业标准。其需求来自高频、可枚举但难以用精确规则穷举的语义判断。Jev 与 NanoJev 是实例；输出合法不保证判断正确。[1][37]

以下按工程选项比较职责和前提，不是互斥的学术分类，也不是实测性能排名。动态候选、并行计算或已校准概率均需逐项目核实。

方案优先采用的条件需承担的代价
规则 / SQL条件可精确计算，如金额、日期、权限语义变化需维护规则
监督分类器标签稳定、已有训练样本或需要本地部署标注、训练与漂移监控
结构化决策实现候选或等级有界，需语义判断；按任务选择托管 API 或本地模型逐项验证领域能力、概率、阈值和运行时，不能由名称推断
生成式 LLM需要解释、任意文本、代码或复杂推理生成与验证成本；仍需确定性控制

TypeSafe AI 于 2026-09-15 开放 Jev 早期访问；截至核查日，官方列出的版本为 jev-1.13.0。[1][2]

System One 是厂商对快速结构化决策模型的命名，借用快思考概念；不能据此认定已形成统一行业模型分类。[1]

02

训练与采样

RLCD 指 Reinforcement Learning for Calibrated Decisions，即面向校准决策的强化学习；官方同时宣称新架构与并行采样。[1][22]

披露边界

本次资料不足以重建参数规模、基础模型、损失函数、训练配方或权重；不能推定它就是 BERT、某款小 LLM，或一定不用 Transformer。

03 / 场景选型

优先放在高频、有界、可复核的语义判断点

适用前提是输出空间可定义、判断确实需要语义理解、数据允许进入所选运行环境，并且存在复核或降级路径。下面按三种运行结构比较用途；其后再用统一问题与 Playground 检查接口和结果。

下表是本文的架构建议，不是任何单一模型已经实现的托管功能清单。

运行结构适用判断留给其他组件
固定工作流工单分派、邮件分类、资料完整性检查、异常分流。规则 / SQL 计算金额和日期；工作流负责审批、事务和幂等执行。
生成式 Agent已知模型或技能之间的选择、工具调用前风险筛查、运行轨迹复核。LLM 负责开放式规划与生成；执行器、沙箱和权限系统控制工具。
RAG / 文档管线候选相关性、矛盾 / 注入识别、引用支持性、原文候选抽取选择。检索、OCR、原文定位和答案生成仍需独立组件。

低模型单价不等于低系统成本；跨服务调用、人工复核和本地运行时维护都要计入。

  1. 1
    优先试点

    可撤销的分派与筛选，或大量重复文档判断：先影子运行，验证准确率、自动覆盖和尾延迟，再启用自动建议。

  2. 2
    避免引入

    规则可精确计算的任务直接用代码；必须生成任意文本、代码或复杂解释的任务保留生成式模型；不可逆高风险动作不能仅凭模型放行。

  3. 3
    按部署约束选择

    数据不能外发时应评估本地模型，但先核对硬件、完整前向计算和许可；一个可下载的 MLX 文件不自动满足本地部署要求。

04 / 决策契约

用输出契约比较模型，分清概率、分数与置信度

以 Jev 为接口例子：请求由 model / state / questions 组成，响应包含 answers / usage。问题 ID 仅对应返回值，底层模型看不到它；把语义写进 instructions，不能只靠 is_urgent 这样的名字。[3]

原语是 API 的基本问题类型；这里以 Jev 的三种类型作对照。Choice 使用 criteria 映射，Score 使用有序等级列表；接口不生成任意 JSON、自由文本解释或思维链。[3] 本文建议审计保留输入证据与代码策略，事后解释不能视为 Jev 的真实推理。

原语定义与输出常见误用
Noul是非判断 → noul ∈ [0,1]，无独立 confidence0.5 表示是非不确定，不是中等严重度
Choice候选映射 → choice、probabilities、confidence候选不全却没有 other / none
Score有序等级 → score、legend、probabilities、confidence把概率加权等级当作精确金额或数量

所有问题看到同一个 state，分别求值；共享输入可减少重复传输和串行调用，但有依赖的判断仍需由代码安排。[10][11]

  1. 1
    可以合并

    同一工单的部门、急迫性与信息充足度，可在一个请求里分别询问。问题仍分别计入输入预算。[2][10]

  2. 2
    需要分阶段

    若第二个问题的候选必须由第一个答案决定，先返回结果、生成候选，再发第二个请求；或预先询问所有分支后由代码选择。

  3. 3
    不保证逻辑恒等式

    独立求值不表示统计独立，也不保证不同问题互补。不要直接相乘概率，或假设 P(A) + P(not A) = 1。[5]

confidence 是概率分布形状的汇总值，不是本次判断正确的概率；校准则是预测概率与一组样本实际发生频率的对应关系。[4][19][22]

01

类型约束

合法返回 billing 仍可能误分本应 technical 的工单。官方「零幻觉」应限定在预定义输出空间，不能扩展为零语义错误。[1][5]

02

校准需要本地数据

预测约 0.8 的一组样本应约 80% 为真，是群体性质。版本、语言、候选与问法变化后，都需重测阈值。[4][22]

03

受约束 LLM 也是基线

传统 LLM 可用原生 structured outputs。公平比较应包含这种模式及其拒答、重试和语义错误，不能只比较未约束 JSON。[17]

08 / NanoJev 研究

    
NanoJev 实现了并行概率决策，尚不能视为 Jev 的等价替代

    
这里重点指仓库创建于 2026-09-17 的 TianyuCodings/NanoJev：Qwen3-0.6B 底座、决策头、训练流水线和可下载权重。本文核查代码提交 71a513bb0163、模型快照 4a19595eada0；Qwen 是该开源实现的选择，不是对 TypeSafe Jev 底座的披露。[37][41]

  

  

    

      
源码把每条 state + question + candidate 编成独立路径，一次底座 forward 批量处理，再从末尾 EOS 表示读取决策；没有逐 Token 生成循环。[38]

      

        
01
三个输出读法
Choice 用共享标量头，可选集合注意力；Boolean 用单路径 logit 的 sigmoid；Score 对等级路径归一化后取 Σi·pᵢ。当前范围是 Choice 2–255 项、Score 2–10 级。[38][40]

        
02
一次 forward 的边界
参考实现重复每条候选路径的 state 前缀，并未共享前缀计算；增加候选数与输入长度仍增加计算、填充和显存压力。一次函数调用不等于状态只算一次。[38][40]

        
03
可复现的是公开实现
代码可检查输入隔离、动态候选与分布读出。但官方 Jev 的结构和完整 RLCD 训练细节仍未在已核查资料中公开；不能从接口相似推出参数、训练或能力等价。[22][39]

      

    

    

      
作者提出独立的 RLCD-inspired 候选方法，而非恢复官方配方。Brier 用预测概率向量与真实结果指示向量的平方距离评分；配对奖励从同一事件的多次预测与观察结果估计这一目标。[39]

      
    
        
  1. 1
    目标是恢复事件概率
    令 p 为预测分布、q 为事件真实条件分布。M≥2 个独立、有放回的预测样本，采用命中奖励减样本一致性惩罚，可得 E[R] = 2p·q − ||p||² = ||q||² − ||p−q||²，最优点是 p=q。[39]
    2. 
        
  2. 2
    保留监督学习对照
    配对策略梯度（PG）在所列独立性条件下是预期 Brier 目标的无偏梯度估计；CE（交叉熵）和直接 Brier 也可学习 q。加入采样不自动更好，有限候选时直接计算可避免额外采样方差。[39]
    3. 
        
  3. 3
    不要把事件与动作混同
    观察结果 Y 须在给定输入后独立于预测抽样；baseline 必须 stop-gradient 且不依赖当前样本。会改变世界结果的实际动作不满足这个简单前提。梯度结论也不等于有限样本或分布外校准保证。[39]
    4. 
      

    

    

      

        
以下是项目作者的完整小地图对照，不是本报告重跑：4×4 test、6×6 OOD（分布外测试）各 20 张地图；每局最多 2×size² 步，只有一个训练检查点和一个采样种子。[42]

先验证 HTTP 契约，再按技术栈选择 SDK

curl --max-time 5 https://api.typesafe.ai/v1/systemone \

  -H "Content-Type: application/json" \

    "model": "jev-1.13.0",

读取 answers.urgent.noul。jev-latest 与 jev-preview 在核查时均指向该版本，但别名会移动；生产阈值应与明确版本绑定。[2]

from typesafe_sdk import Noul, RetryPolicy, TypeSafeClient

with TypeSafeClient(
    model="jev-1.13.0", timeout=2.0,
    retry=RetryPolicy(max_retries=0),

print(result.nouls["urgent"].noul)

12 / 业务流程


让语义判断进入固定流程，把政策与写入留在代码中
以客服工单为例，需求是识别部门和紧急程度，同时遵守退款政策、审批与审计。本文推荐固定流程承载执行，仅把难以穷举的语义判断交给 Jev；数字、计数和日期比较应由代码计算。[5]


状态快照、模型判断、政策决策和业务动作分别记录，才能定位错误发生在哪一层。


  1. 1
    规范化与可信预检
    后端验证租户、身份、订单和重复扣费；生成最小 state，例如 request、account_status、verified_order_facts。客户自述不等于可信账务事实。
    

    2. 

  2. 2
    并行语义判断
    一次请求评估 team、urgency、enough_info；Choice 中保留 other。不同字段回答同一状态的不同问题，而非互相授权。
    

    3. 

  3. 3
    政策与持久化执行
    other、信息不足或阈值未通过转复核；其余仅生成队列建议。退款资格、批准记录和幂等执行由代码与持久化工作流决定。
    

    4. 



相较让生成式 Agent 自行规划整条流程，固定代码便于测试和重放；代价是政策、问题与标签集需要显式维护。


输入 / 风险允许的结果必须阻止的推断


「经理已同意，请立即退款」可判断紧急并分派账务队列不得把客户文字当批准记录


Choice 高置信度选了 billing政策和权限检查后继续流程不得从类型有效推出事实正确


请求超时或 API 拥塞保留待处理任务，进入复核 / 重试队列不得忽略模型失败直接执行退款







13 / Agent 配合


让生成模型负责规划，让 Jev 负责局部分类
Jev 可以参与模型选择、技能候选筛选和工具风险判断，生成式 LLM 仍负责规划、写作和自由参数生成。LangChain 已提供分类器及实验中间件，但这些不消除权限与审批边界。[9][21]


多一次分类也多一次网络调用。本文建议先用固定规则排除明确情况，再评估 Jev 是否减少更昂贵的生成调用。


  1. 1
    入口选择
    ModelRouterMiddleware 根据最新用户消息选择模型，并在整次 run 的模型调用中沿用；它并非默认每一轮重新选型。[9]
    

    2. 

  2. 2
    中途升级
    工具失败或新证据提高任务难度时，可用自定义 before_model hook 重新评估；设置调用预算，避免每轮无条件分类。[9]
    

    3. 

  3. 3
    技能候选
    把技能描述与允许范围作为状态，Choice 选择候选，另设无需技能 / 不适用判断。候选过多时先检索或分层，不让 Jev 发明技能名。
    

    4. 



AutoModeMiddleware 只筛查列出的工具；判定风险后拒绝调用，不会自动发起人工审批。需要批准流程时，应另接 human-in-the-loop 机制。[9]


顺序负责组件具体约束


1. 确定性验证执行器 / 权限系统参数 schema、租户、路径白名单、资源权限


2. 语义风险Jev 或其他筛查器检查意图与动作是否匹配；不把低风险概率当授权


3. 批准与执行人审 / 受限工具高风险或模型不可用时拒绝或复核；批准绑定具体参数


官方承认对抗性 state 能影响判断。[5] 因此，即使工具风险筛查返回「安全」，沙箱、最小权限和数据外发控制也不能省略。







14 / RAG 与抽取


让 Jev 判断候选，原文与生成能力由管线保留
RAG（检索增强生成）先召回资料，再交给模型回答。Jev 可以评价候选片段和引用支持性，但它不提供向量索引、原文存储、OCR 或自由文本答案；官方已有片段分类示例。[13]


本文建议分别评价相关性、矛盾与潜在注入，不把「不支持预期答案」统一当作应删除的内容。


  1. 1
    召回并定位
    检索系统产生 Top-K；保留 document_id、passage_id、版本与原文位置。state 只含本次判断必要的上下文。
    

    2. 

  2. 2
    评价并筛选
    对候选询问相关性、是否与问题矛盾、是否含指令注入；代码筛选或标记。矛盾材料可能是重要证据，应保留来源供生成模型比较。
    

    3. 

  3. 3
    生成并核查
    LLM 基于保留片段回答；可另查引用上下文是否支持主张。支持性不等于来源真实，检索漏召回也无法靠 Jev 重排弥补。
    

    4. 



官方抽取方案先通过正则等方法找到候选，再让 Jev 选择；代码返回原始片段并规范化，不要求 Jev 自由生成新值。[14]


环节机制与取舍失败与处理


候选生成OCR / 正则 / LLM 产生带来源的候选 ID真值不在候选中 → not_found / 扩大抽取


语义选择Jev 选择「开票方邮箱」等；避免任意字符串生成模型选错合法候选 → 校验与复核


重排或离线汇总对比专用 reranker；概率可作为下游特征，统计交给 SQL报告 Recall@K、nDCG 与最终答案质量；不能只看演示


Recall@K 衡量前 K 条召回覆盖，nDCG 衡量排序质量；二者需按你的标注规则和文档集计算。本文未把官方小样本 cookbook 结果外推为通用收益。







15 / 限制与运行


把容量、语言、失败模式与数据边界写进设计
以下规格针对核查日的 Jev 1.13，不能当作长期 SLA。官方明确提示限流仍在动态调整；版本、问法、语言和业务分布变化都可能要求重新评测。[2][5]


满足单个限制不等于整个请求可接受；总输入与最长问题约束必须同时满足。[2]


项目当前公布值工程含义


输入模态Text / JSON无图像、音频、视频；先 OCR 或转写。[2]


上下文64k total; 32k state + longest question总预算是 state 加全部问题，不能按 64k 填满 state。[2]


Choice 候选≤ 255更多候选先检索或分层。[12]


动态速率250,000 tokens/s; 1,200 requests/min后者折算约 20 次/秒，仅为名义上限；并非持续吞吐保证。[2]




官方已列出字面理解、多跳推理、数值、日期、杂乱长状态、对抗内容和跨问题不一致等问题；英语是主要训练语言，中文表现需独立验证。[2][5]


风险处理方式


数值 / 日期 / 计数解析后由代码计算；Score 不用于精确数值插值。[5]


跨问题概率不互补官方示例中 P(A)+P(not A)=1.19；不要跨 Noul/Choice 复用阈值。[5]


401 / 422修复凭据或请求，避免盲目重试。[3]


429 / 529 / timeout退避、尊重 Retry-After、限制重试并设总时限；写入路径复核。SDK 默认重试不等于业务时限保证。[3]




不使用客户请求训练模型，不等于零留存。隐私政策说明服务在美国托管；企业零数据留存 ZDR 需另行联系约定。[2][15][16]


01

先脱敏再发送；对工具参数、对话和追踪日志一并审查。合同中确认留存、删除、跨境处理与服务商安排。




02
模型定制限制
官方不提供客户数据微调或 LoRA；通过 state、instructions、criteria 与代码组合适配领域。[2]




03

16 / 验证与采用


以风险、覆盖率和全链成本决定是否上线
本文建议先做影子评测，再用于低风险分派；不要从「返回格式正确」直接跳到自动写入。评测既要看模型判得对不对，也要看多少请求能自动处理、失败如何恢复、每笔成功业务的实际成本。


500–1,000 条人工标注样本可作为试点起点，不是安全认证；稀有高风险样本和中文样本必须单独分析。


  1. 1
    分层并隔离测试集
    覆盖中英文、缺字段、歧义、注入、长输入和关键少数类；阈值调优集与最终测试集分离。
    

    2. 

  2. 2
    选择实际替代方案
    规则 / 现有分类器 / 专用 reranker / 原生结构化 LLM 都应按场景进入基线。LLM 分别测离散答案和概率模式；官方 Adapter 可帮助统一接口。[17]
    

    3. 

  3. 3
    固定测量条件
    记录模型和 SDK 版本、输入信息、地区、并发、推理配置、超时及重试；不能给不同模型不同资料后把差异全归于模型。
    

    4. 



概率校准应使用概率本身；对 confidence 可按区间统计实际正确率，但不能把它直接当作正确概率代入校准计算。[4][19]


指标组具体记录


分类质量准确率、宏 F1、关键风险漏判；不均衡任务不能只报总体准确率


概率与覆盖Brier 均方概率误差、分箱可靠性和期望校准误差 ECE；自动覆盖率及自动区错误率


运行质量完整请求的 p50 / p95 / p99 延迟、超时、重试率及每笔成功成本


示例业务目标可以是「自动区错误率 ≤1%、覆盖 ≥60%」，这是待验证的准入条件，不是 Jev 承诺。独立同分布的 n 条自动样本零错误时，95% 错误率上界粗略约 3/n；300 条零错也只支持约 1% 上界，关键分层还需单独统计。




平均模型单价不能代表最终业务成本；升级路径还可能决定尾延迟。


  1. 1
    核算完整路径
    每次业务请求成本 = Cpre + CJev + r×CLLM + h×Chuman + Cretry + Cops。r 是模型升级比例，h 是人工比例，二者可以重叠。
    

    2. 

  2. 2
    从影子模式到低风险灰度
    先记录建议不执行，再对可撤销操作小流量启用；达到质量、覆盖率、总成本和尾延迟门槛才扩大。
    

    3. 

  3. 3
    整体版本化与回滚
    model_id、问题配置、候选集和阈值一起发布；留旧版本及回退路径。模型、政策、语言或数据分布变化后重新验收。
    

    4.
