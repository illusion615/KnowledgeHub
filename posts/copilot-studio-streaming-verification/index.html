00 / 快速决策

先按 Agent shape 与 transport 选择四条路线之一

01 / 共同前置

四条路线共享 Agent 识别、时序指标与统一事件模型

Transport 可以不同，但客户端最终都要生成同一组 turn events。统一术语与完成判据后，UI 不需要理解 Direct Line 或 D2E 的原始字段。

实现前收齐下列信息；缺任一项时不要开始拼接 URL。

Connector 负责 transport 与 raw activity 解析；Turn reducer 只接收以下事件。

02 / D2E 身份模式

Delegated 是实施身份；S2S 仅保留为 Private Preview 边界证据

Copilot Studio Client 的 D2E 请求始终携带 Power Platform Entra JWT。本文实施路线只使用用户 delegated token。Private Preview 文档中的 app-only 与 OBO S2S 模型仅用于解释 token claims、Agent 认证模式和 ACL 差异，不构成选型、Runbook 或交付承诺。 [14]

Microsoft 的 S2S 预览文档把 app-only 与 delegated OBO 都归入 S2S；为避免混淆，本文分别称为 app-only S2S 与 delegated OBO。两者都只作 Private Preview 事实对照，不进入实施范围。

本节只解释为什么 application permission 不代表能力可用：Private Preview 运行时还会检查预览开关、Agent ACL、认证模式、租户和会话调用者一致性。它不是实施 Runbook，也不把 S2S 纳入候选方案。

  1. 环境级 Private Preview feature gate

    该预览由 Microsoft 按目标环境或租户控制；Entra 中出现 application role 不能证明运行时已经开放。

  2. 同租户 application permission

    预览文档要求 Power Platform API 的 CopilotStudio.Copilots.Invoke application permission 与管理员同意，并声明不支持跨租户。 [15]

  3. 应用身份 Agent ACL

    预览模型要求应用身份在 Copilot Studio 分享 ACL 中拥有 viewer 权限；仅有 tenant consent 不满足 Agent ACL。

  4. No Authentication 依赖

    App-only 请求没有最终用户，不能运行依赖用户登录、用户连接或 OBO 的工具；该认证模式不代表 D2E endpoint 可无 JWT 调用。

  5. 会话调用者一致性

    预览文档规定同一会话使用同一应用身份；调用者或身份类型变化会返回 CallerIdentityMismatch 或 CallerIdentityTypeMismatch。

身份、Agent 认证、transport 和产品生命周期必须分别判断；任一层成立都不能替代其他层的证据。

常见说法准确解释
配置了 ClientSecret 就是 S2S不成立。Confidential client 也能执行 OBO；以 token 的 idtyp、scp 与 roles 判断身份类型。
Agent 是匿名模式，所以 D2E 可匿名调用不成立。No Authentication 只关闭最终用户登录；PPAPI 仍要求有效的 Power Platform Entra JWT。
S2S 会改变 streaming 协议不成立。S2S 只改变调用者 token 与 ACL；Accept: text/event-stream 和 Activity SSE 处理保持不变。
S2S 等同 Direct Line不成立。Direct Line 使用 Bot Framework secret/token 与 WebSocket；S2S 仍通过 PPAPI D2E 和 Entra JWT。
路线前置依赖采用判断
D2E delegated用户登录、delegated permission、Agent 分享公开 SDK 路径；适合有 Entra 用户的当前集成
Gateway + 专用 delegated 用户管理员一次性交互登录、delegated permission、Agent 分享、加密 MSAL token cache当前可实施主方案：第三方只调用 Gateway，不接触 Entra；Gateway 代表同一个专用用户调用现有 /3p D2E streaming。

专用 delegated 用户 Gateway 若经过 Azure API Management，forward-request 必须设置 buffer-response=false；默认缓冲会延迟 Copilot Studio SSE chunk 到达客户端。 [17]

03 / Classic + Direct Line

Classic Agent 通过 Direct Line WebSocket 接收 livestreaming activity

适用于已经发布 Direct Line channel 的 Classic Agent。客户端通过短期 Direct Line token 建立 conversation 与 WebSocket，并在 activity 上声明 deliveryMode: 'stream'；目标环境是否实际下发 progressive chunks 仍须用 raw activity 验证。

该路线使用 Direct Line 3.0 REST + WebSocket；secret 只保留在服务端，浏览器只接收短期 token。

字段规格
支持状态BotFramework livestreaming contract 支持；是否下发 progressive chunks 由目标环境决定
TokenPOST https://directline.botframework.com/v3/directline/tokens/generate
服务端用 Direct Line secret 换短期 token
ConversationPOST /v3/directline/conversations
返回 conversationId、token 与 streamUrl
ReceiveWebSocket GET {streamUrl}
SendPOST /v3/directline/conversations/{conversationId}/activities

先启动 WebSocket，再发送 startConversation event 和用户 message；接收端逐个归一化 ActivitySet 中的 activity，不按 activity 数量创建气泡。

const directLine = createDirectLine({ token, webSocket: true }) directLine.postActivity({ type: 'event', name: 'startConversation', deliveryMode: 'stream', from: { id: userId }, entities: [{ type: 'ClientCapabilities', requiresBotState: true }], }).subscribe() directLine.postActivity({ type: 'message', text, deliveryMode: 'stream', from: { id: userId }, }).subscribe() directLine.activity$.subscribe(activity => reduceTurnActivity(activity))
返回类型处理规则
typing只更新工作状态；空文本不创建答案气泡
streaminfo从 channelData 或 entities[type=streaminfo] 读取 streamType、streamId、streamSequence 与 chunkType
answer chunk按 streamId 更新同一个答案状态；无 ID 首 chunk 先绑定本地 turn ref，真实 ID 到达后建立 alias。chunkType 只作诊断，合并以文本关系为准：incoming 相同或以 current 开头时替换；长文本共享显著前缀时按 revised snapshot 替换；否则追加为 delta
final message通常完成同一个答案状态并建立 tombstone；若 final 明显更短且与已流出答案前缀低重合，保留 streamed answer，把 final 作为单独 fallback message。晚到 chunk 不得新建气泡

验收必须同时检查 secret 隔离、WebSocket 时序和最终 UI；只收到 final message 属于目标环境的 final-only 结果，不应误判为连接失败。

  • 安全：浏览器、日志和导出文件均不得出现 Direct Line secret。
  • 时序：按 streamSequence 丢弃重复或倒序 activity；Classic reducer 不把 chunkType 当作权威值，使用 mergeStreamingText 的 prefix/overlap 规则。
  • Transport gate：WebSocket 在线，并收到目标 conversation 的 ordered ActivitySet。
  • Progressive gate：至少两个不同的非空答案快照，且 sequence 单调递增；只收到 final 不算 progressive。
  • Reducer/UI gate：正常 final 只完成一个答案气泡；divergent fallback final 不覆盖已流出答案；晚到 chunk 不增加消息数。
  • 降级：空 typing 后只有一个完整 message 时，记录为 final-only，并保留 ordered activity dump。

下载脱敏 Direct Line final-only observed capture — 只证明该环境的 transport 与 final-only 判定，不证明 progressive streaming。

04 / Classic + D2E

Classic Agent 使用 published-bot D2E endpoint

适用于已 Published 的 Classic Agent。实施路径由浏览器或 Gateway 通过 MSAL 获取 delegated Power Platform token，并要求 Agent 已共享给当前用户。本章只覆盖 delegated published-bot endpoint、HTTP POST 和 SSE activity。

接口 host 来自 environment ID；建会话和发送 turn 都是 POST，同一响应以 text/event-stream 返回 activity。

SDK URL 不含 /conversations；SDK 会在 query string 之前插入路径。手写 fetch 时必须直接构造表中的完整 URL，不能在 ?api-version 后追加路径。

以下样例展示 interactive delegated。建会话 POST 返回后先从 x-ms-conversationid header 保存 conversationId，再消费 SSE。仅 startConversation 不会产生用户问题对应的答案。

const token = await msal.acquireTokenSilent({ scopes: ['https://api.powerplatform.com/.default'], account, }) const client = new CopilotStudioClient({ directConnectUrl }, token.accessToken) for await (const activity of client.startConversationStreaming({ emitStartConversationEvent: true })) { conversationId ||= activity.conversation?.id || client.conversationId reduceTurnActivity(activity) } for await (const activity of client.sendActivityStreaming(message, conversationId)) { reduceTurnActivity(activity) }

HTTP header 先确定会话，SSE parser 再按事件边界恢复 Activity JSON；终止 marker 不进入 UI。

返回内容处理规则
x-ms-conversationid优先保存为后续 turn URL 的 conversationId；SDK 内部值作为回退
SSE event/data按空行切分事件，合并同一事件的多行 data，JSON.parse 后才交给 reducer
[DONE] / event: end不创建 UI 消息。当前 MCSChat connector 忽略该事件并继续读到 response body EOF；若实现选择立即 cancel reader，必须先确认目标 runtime 不会在 marker 后发送有效 activity

Reducer 按 stream metadata 分类 activity，并在 final 前后维护 active state、alias 与 concluded tombstone。

返回内容处理规则
streamType=informative更新工作状态，不进入答案 assembler
streamType=streaming / streamSequence空文本忽略；按 sequence 去重；用 streamId 找同一 answer state；chunkType 只作诊断，调用 mergeStreamingText 按 prefix/overlap 区分 cumulative、revision 与 delta
streamType=final / message + streamId先把 streamId 及全部 alias 写入 concludedStreams tombstone，再删除 active state；后续命中 tombstone 的 chunk 直接丢弃。有内容时用 isDivergentFallbackFinal 比较 streamed/final：正常 final 完成同一 answer state；divergent final 保留流式答案并作为独立 fallback；空 final 触发 streamCancelled 并移除临时消息。当前 DirectEngineConnector 尚未接入 Classic tombstone 与 divergent branch，实施时必须补上
普通 typing / messagetyping 只更新状态；无活动 stream 的 message 作为完整消息或 greeting

获得 token 不等于 Agent 可调用。Delegated 需要核对 redirect URI、token audience、用户权限与 Agent 分享关系。

现象核对
AADSTS50011请求 redirectUri 与 Entra SPA 注册值逐字一致；MCSChat 使用 window.location.origin。
403 InsufficientDelegatedPermissions读取 response body 列出的缺失权限；不要假设单一权限在所有租户都充分。
D2EAccessDenied检查 delegated permission、管理员同意、用户权限和 Agent 是否共享给该用户。
CallerIdentityMismatch同一 conversation 中更换了用户；重建 conversation，且后续 turn 保持原调用者。
401检查 token aud、有效期与实际 SPA account。
404 / 403确认 Agent 已 Published、schemaName 正确，并已共享给 delegated token 对应用户。
SSE 无答案保留 HTTP status、response body、event count 与脱敏 activity；不要只根据 UI 判定根因。

能力验收分成 transport、progressive 与 reducer/UI 三道门；任一道失败都要保留对应原始证据。

  • 能力边界：当前 D2E connector 不支持文件上传；需要附件时改走 Direct Line 或另行验证官方能力。
  • 非 2xx：应用层必须设置超时；SDK 调用持续等待时，用手写 fetch 预检保存 status/body 后中止，不做无限重试。
  • Transport gate：建会话与发送 turn 均返回 2xx，conversationId 稳定，SSE 完整结束。
  • Progressive gate：至少两个不同的非空答案快照；只收到完整 final 时记录为 final-only。
  • Reducer/UI gate：正常 final 只完成一个非空答案气泡；divergent final 允许在保留 streamed answer 后增加一条独立 fallback message；日志不含 access token。

05 / New + Direct Line

New Agent 的 Direct Line 可用性取决于 harness 与认证模式

这不是一条可直接照抄的正式接口路线。对 GitHub Copilot harness，Microsoft Learn 当前把 Native app / Direct Line 标为不可用；其他 New Agent shape 只有在目标环境明确提供 channel、token bootstrap 和 routing contract 时才可实验。

缺少任何一项正式字段时，规格结论就是“当前不可实施”，而不是套用 Classic Direct Line endpoint。

字段规格
支持状态GitHub Copilot harness：Native app / Direct Line = No；其他 shape 取决于目标环境当前渠道矩阵
Endpoint没有适用于所有 New Agent 的公开稳定 Direct Line endpoint；必须由目标环境的官方 bootstrap 返回
Methodbootstrap 未确认前无可声明规格；bootstrap 成功后才进入 Direct Line 3.0 REST + WebSocket
Authentication由目标 shape 的 channel / bootstrap contract 决定；不得把 D2E Power Platform token 当作 Direct Line token
Request只有官方返回或样例明确要求时，startConversation 才携带 cci_bot_id / cci_environment_id
Responsebootstrap 返回 Direct Line domain/token/routing contract；POST /conversations 再返回 conversationId/token/streamUrl；WebSocket 返回 ActivitySet。三层都必须保存脱敏 capture 后才能确认实际 schema
默认替代路线New Agent + /3p D2E

只有目标环境已经返回可用 token、Direct Line domain 和 routing contract 时，才执行以下实验流程；否则在接口发现阶段停止。

  1. 确认 channel 与 bootstrap

    记录 harness、认证模式、bootstrap URL、HTTP status 与脱敏 response schema。

  2. 使用返回值建会话

    使用返回的 Direct Line domain 与 token；仅按 contract 添加 routing IDs，不自行猜测字段。

  3. 处理 ActivitySet

    沿用 Direct Line 的 ActivitySet 分发，但先保存 raw activities，再根据真实 streaminfo / payload 决定 reducer。

  4. 形成环境限定结论

    报告具体 Agent shape、日期与环境；不得外推为所有 New Agent 的 Direct Line 支持。

这条路线的第一项验收不是“能收到消息”，而是接口来源、认证方式与支持边界均可追溯。

  • 禁止直接复用 Classic Direct Line token endpoint、domain 或 payload 假设。
  • bootstrap 返回 404 / 403，或缺少 Direct Line domain/token/routing contract 时停止；bootstrap 成功后，conversation response 缺少 conversationId/streamUrl 时同样停止。不得用隐藏 endpoint 或硬编码 routing ID 绕过。
  • 通过：保存脱敏 bootstrap response、实际 Direct Line domain、startConversation request、ordered ActivitySet，以及一个完整 turn 的 UI 断言。
  • 未满足通过条件时，产品默认选择 New Agent /3p D2E。

09 / Gateway 挑战与定位

D2E Streaming Gateway 以专用用户代替第三方登录，并保持现有 New Agent 的真实流式输出

第三方用户没有 Microsoft Entra 账号，但现有 New Agent /3p D2E streaming 已能由一个有权限的 Entra 用户调用。Gateway 位于第三方与 Copilot Studio 之间：管理员先让专用服务用户完成一次交互登录，Gateway 加密保存 MSAL token cache，随后静默获取 delegated Power Platform token，并把既有 D2E SSE 转成稳定的外部 API。第三方不参与 Microsoft 登录，也不会接触上游 token。

01

平台身份隔离

调用方没有 Entra 身份，D2E 却要求 delegated Power Platform token。Gateway 保护专用用户的 MSAL cache；外部访问控制机制由项目选择，不限定为客户 JWT。

02

流式接口不匹配

客户需要稳定的自定义 SSE API；D2E 返回平台 Activity SSE 和运行时特有事件。Gateway 负责解析、归一化、脱敏并立即转发。

03

共享上游用户下的客户隔离

所有 D2E 请求共享同一个专用用户，Copilot Studio 不认识外部客户。Gateway 必须独立承担租户授权、会话归属、配额、幂等和审计；Microsoft 审计会显示该专用用户。

定位：Gateway 是面向外部客户的流式接入边界，也是 D2E 的身份代理、协议适配与会话控制层；它不替代客户 IdP，不赋予最终用户 Entra 身份，也不改变 Copilot Studio Agent 的业务逻辑。

11 / Gateway 外部接口与边界

Gateway 代表专用用户调用同一个 Agent，并向无 Entra 账号的客户提供隔离的 SSE API

Gateway 使用专用 Entra 用户的 delegated token 访问 D2E。管理员只在初始化或 Conditional Access 要求重新认证时参与 Microsoft 登录；第三方调用始终使用 Gateway 自己的访问控制。Agent 的 No Authentication 关闭最终用户登录，但不会让 D2E endpoint 变成匿名接口。每个 conversation 始终绑定同一个专用用户，不得在会话中更换身份。

12 / Gateway 运行时与状态

专用用户身份、会话锁与禁止重放规则共同保护每个 turn

Gateway 只为已完成 delegated live probe 的 Agent 开放专用用户路线；身份状态必须为 ready，同一 conversation 串行执行 turn。D2E POST 发出后禁止自动重试，避免同一输入执行两次。

路由配置与会话状态分别持久化；没有当前 live probe 证据的 Agent fail closed。

参考实现只服务单一 Agent：environmentId、schemaName、apiVersion 和上游 scope 均来自启动配置，agentId 在建会话时校验 allowlist。身份状态是全局的，不按 Agent 分开记录。

RouterConfig { environmentId: GUID // 推导 environmentHost schemaName: string apiVersion: string scope: 'https://api.powerplatform.com/.default' upstreamTimeoutMs: number conversationTtlMinutes: number } IdentityState = 'ready' | 'reauthRequired' | 'disabled'

多 Agent 路由尚未实现。若要扩展，需要把 environment/schema/身份绑定与活体探测证据一起下沉到每个 agentId，并对没有当前证据的 Agent fail closed。

localhost 实现把 encrypted MSAL cache、account metadata 与 conversation JSON 分开保存到 mode-600 文件。所有写入先落同目录临时文件，再用原子 rename 替换；SHA-256 ETag 防止并发覆盖。会话记录不包含 access token、refresh token、cache blob、UPN 或答案正文。

GatewayConversation { id: opaque UUID subjectHash: SHA-256 agentId: string upstreamConversationId: string status: 'active' | 'busy' // 过期在读取时判定，不写回状态 recentTurnIds: string[] activeClientTurnId?: string createdAt: timestamp updatedAt: timestamp expiresAt: timestamp version: number lockOwner?: string lockExpiresAt?: timestamp }

默认会话 TTL 为 60 分钟；turn lock 等于 upstream timeout 加 30 秒，当前配置为 210 秒。recentTurnIds 最多保留 100 个 clientTurnId。每次变更都要求 ETag 匹配；若 D2E POST 的结果不确定，Router 不自动重放。该 local store 只支持单主机原型，不声明多实例一致性。

实现必须保持端到端流式并明确失败发生在首个字节之前还是之后；两种情况使用不同的错误通道。

  1. 认证并授权外部调用

    从已验证凭据派生客户主体，核对 Agent allowlist、速率、并发与请求大小；失败时不得调用 Entra 或 D2E。

  2. 锁定会话并静默获取上游 token

    Gateway 从加密 MSAL cache 加载专用用户账号，调用 acquireTokenSilent 获取 https://api.powerplatform.com/.default delegated token。MSAL 负责 refresh token 轮换；Gateway 不直接读取或持久化单独的 refresh token。

  3. 调用 D2E 并立即转发

    上游请求携带 Accept: text/event-stream；Gateway 按空行解析 SSE，完成 reducer 后立即 flush。超时判定与流取消只实现在一条帧读取路径上，Activity 解析删减在其上层叠加，避免两条下游契约各自维护一份不一致的超时逻辑。当前 localhost 链路没有反向代理；未来如加入 APIM 或其他代理，必须关闭响应缓冲。

  4. 尝试取消并释放本地状态

    客户端断开或超时时，Gateway 中止本地 upstream fetch 并在 finally 中释放租约。该动作不保证 D2E 服务端停止处理或停止计费；目标环境必须单独验证。

13 / Gateway 安全、观测与验收

调用方访问控制、敏感信息保护和故障测试构成试点门槛

固定安全要求是保护专用用户与加密 MSAL cache、限制调用来源并避免敏感日志。专用用户应独立于个人账号，只授予 Agent viewer 与运行所需的最小权限；Conditional Access、MFA、账号禁用和 consent 撤销都可能触发管理员重新登录。外部认证机制由项目选择，Gateway 始终承担客户隔离责任。

启用多租户访问控制时，tenantId 与 subject 必须从已验证的服务端身份映射派生，不接受客户端直接传值；隔离 POC 不声明多租户隔离能力。

  • 访问控制：若选择 OIDC，只允许批准算法并校验签名、issuer、audience、有效期和 JWKS；若选择 API key 或 mTLS，按项目的密钥轮换或证书链策略校验。
  • 日志：禁止记录 Authorization、token、secret、私钥、完整 prompt/answer、raw Activity 与工具参数；默认只记录长度、哈希、状态和时序。
  • 追踪：生成或传播 correlationId 与 W3C traceparent；审计包含 tenant、subjectHash、agentId、conversationId、clientTurnId、outcome、upstreamStatus、durationMs、chunkCount、disconnectReason。
  • 指标：请求数、活动流、Gateway 附加延迟、上游错误、断开、锁竞争和 token cache hit；只按 tenant、agentId、outcome 分维度。

当前实现验收 dedicated delegated 身份、token-cache 生命周期、D2E transport、SSE、取消和错误通道。只有启用相应能力时，才追加外部身份、持久状态、隔离、并发和幂等测试。只检查 UI 不构成通过。

  • Delegated 身份：identityState=ready 且 evidence 未过期；验证 aud、tid、有效期、idtyp=user 与 scp 包含 CopilotStudio.Copilots.Invoke；token 中的用户对象必须匹配已注册专用账号。
  • Token cache：进程重启后能从加密 cache 静默取 token；并发写入不丢 refresh 状态；模拟 interaction_required 后不调用 D2E、返回 503，并在管理员重新登录后恢复。
  • 条件验收 · 隔离：启用多租户身份时，客户 A 使用客户 B 的 conversationId 得到 404，且上游调用计数不增加。
  • 条件验收 · 并发：启用多轮会话时，同一会话并发发送两个 turn 只有一个进入 D2E；不同会话可以并行。
  • 流式：progressive 样本至少两个不同的非空 answer snapshot 在 final 前到达；2026-08-18 浏览器样本观测到 4 个。final-only 或单 snapshot 由上游决定，必须明确记录。生产评估还需单独测量 Gateway 附加延迟 P50/P95。
  • 断开：客户端断开后 Gateway 发出本地 abort、释放本地执行状态且不再产生出站字节；若启用租约则同时释放租约。单独报告 D2E 服务端是否继续处理。
  • 幂等：同一会话重复 clientTurnId 不产生第二次 D2E turn。建会话幂等尚未实现；若后续引入，应验证相同主体与幂等键不创建第二个会话。
  • 契约回归：相同提问分别走直连与透传通道，导出的 Activity 序列除 conversation.id 外逐字段一致；任何其他差异都说明 Router 改变了 D2E 数据结构。
  • 失败：首字节前错误使用 HTTP status；首字节后错误使用 SSE error；两种情况都带 correlationId 且不暴露上游响应正文。
