Copilot Studio New Agent Pattern

把经典 Knowledge Agent 迁移到 New Agent

本文记录一次 Copilot Studio 知识问答迁移实践：经典 Knowledge Agent 依赖 topic flow、unbound action 和 AI Prompt；New Agent 改用 Instructions、Skills 和 Tools 复刻同一套 Dataverse 知识检索能力，并通过参数契约和答案规范降低重试成本。

01 / Problem

经典 Topic 编排可以复刻，但 New Agent 需要显式契约

本章说明迁移要解决的问题：保留原有知识域选择和接地回答，同时减少 Agent Flow 与 AI Prompt 的额外往返。

Classic Agent

显式 Topic Flow 串联检索与生成

  • 通过 Flow 读取知识域列表，再用 Question 节点保存用户选择。
  • 调用 copilotquerytextcontext 检索 faq_article。
  • 再调用独立 AI Prompt 将检索结果生成答案。
New Agent

工具只负责检索，编排器直接生成答案

  • Skills 固化域选择与检索规则，Tools 连接 Dataverse MCP 与 unbound action。
  • 答案生成不再额外调用 AI Prompt，减少一次模型往返。
  • 参数类型、域过滤和 fallback 必须写成硬规则，否则模型会重试或串域。

02 / Data Contract

两张表承担两个边界：域列表与答案正文

上一章明确迁移目标，本章把目标落到 Dataverse 数据契约：域列表不来自文章表，答案检索不来自 Topic 表。

用途表字段规则
知识域列表faq_topicbiz_groupname读取非空值后去重，作为用户可选 knowledge domain。
答案检索faq_articlefaq_articlebody只检索正文列，并用 biz_groupname 过滤当前域。
串域防护faq_articlebiz_groupname生成答案前二次检查返回记录，字段不等于当前域的记录必须丢弃。
Unbound Action Contract

copilotquerytextcontext 的参数类型必须显式写入 Skill

  • organization 必须传 current，传完整 CRM URL 会导致 Request validation 400。
  • options 必须是 JSON 字符串：{"VectorSearchMode":"Hybrid","UseVectorSearch":true}。
  • entityParameters 必须是 JSON 字符串数组，不能传原生 array。

03 / Implementation

Instructions 定边界，Skills 定步骤，Tools 做外部调用

数据契约明确后，New Agent 的实现重点变成编排约束：哪些行为由全局 Instructions 约束，哪些行为进入可复用 Skill。

01

会话开始主动列域

调用 Dataverse MCP 查询 faq_topic.biz_groupname，去重后列出 7 个知识域，让用户选择。

02

用精确域名更新状态

用户消息中出现完整域名时，例如 Lenovo IVA Troubleshooting，直接把该值作为当前域。

03

检索后再次过滤域

即使 action 已设置 filterCriteria，答案生成前仍检查每条记录的 biz_groupname，不匹配就丢弃。

04

按原 Prompt 规范生成答案

保留语言一致、Markdown、引用、References、图片输出和固定 fallback。

Instructions

写全局边界，不写工具流水账

Instructions 负责角色、数据模型、当前域状态、跨域过滤、图片保留和固定 fallback。这些规则必须覆盖所有回合，因此不能只放在单个 Skill 中。

Skills

写可触发步骤，明确工具参数

Skills 负责选域和回答两个可触发流程：select-knowledge-domain 管 faq_topic 域列表，answer-from-knowledge 管 unbound action、后过滤和答案格式。

New Agent 的写法分成三层：Instructions 写不可违反的全局边界，Skills 写可触发的行为步骤，Tools 只承接外部系统调用。

层级 写入内容 设计原因
Instructions 角色、数据模型、域选择状态、fallback、图片保留、跨域丢弃等全局约束。 这些规则必须覆盖所有轮次；若只写在某个 Skill 中，模型在域选择或异常分支中可能绕开。
select-knowledge-domain 从 faq_topic 读取 biz_groupname，去重、排序、展示给用户选择；失败时换查询方式重试。 域列表是对话入口行为，不应混进回答 Skill；否则 greeting、切换域、直接带域提问三种场景会互相干扰。
answer-from-knowledge 调用 copilotquerytextcontext，明确 organization=current 与 JSON 字符串参数；生成前过滤 biz_groupname。 参数类型错误会造成 400 重试；检索返回中的域名错误会造成引用串域。两者都必须作为步骤写明。
答案规范 同语言、Markdown、References、编号引用、图片输出；无命中时只返回固定句子。 这是替代经典 AI Prompt 的部分；New Agent 不再调用独立 Prompt，因此必须把原 Prompt 的格式规则迁移到 Skill。

以下是本次 New Agent 的实际配置取值。Tools 已挂载「Perform an unbound action in selected environment」与「Microsoft Dataverse MCP Server」两项。

1. select-knowledge-domain 的域查询：在 Dataverse MCP 上读取 faq_topic 表的 biz_groupname 列，客户端去重后展示。

SELECT biz_groupname FROM faq_topic

2. answer-from-knowledge 调用 copilotquerytextcontext 的精确入参：

参数 类型 取值
organization字符串current
searchText字符串用户的问题原文
searchType字符串semantic
searchMode字符串any
options字符串（JSON）{"VectorSearchMode":"Hybrid","UseVectorSearch":true}
top数字3
totalResultCount布尔false
entityParameters字符串（JSON）[{"name":"faq_article","searchColumns":["faq_articlebody"],"filterCriteria":"biz_groupname eq '<SELECTED_GROUP>'"}]

<SELECTED_GROUP> 替换为当前域显示名；域名中的单引号需翻倍转义。options 与 entityParameters 必须作为字符串传入，否则返回 Request validation 400。

3. 固定 fallback 话术：检索剩余上下文不直接回答问题时，只输出对应语言的固定句子，不附加解释或 References。

  • 英文：Sorry, I cannot find relevant information in the knowledge library.
  • 中文：抱歉，我无法在知识库中找到相关信息。

New Agent 的纯 Instructions / Skills 无法稳定生成经典 Topic 的 suggested-action chip。若需要原版那种可点击域按钮，应让工具返回 Adaptive Card。

  • 可选增强：Agent Flow 查询 faq_topic 后返回 Adaptive Card，卡片按钮用 Action.Submit 提交域名。
  • 会话开头固定 Suggested Prompts 只能作为 starter prompts，不能替代每轮动态按钮。

检索到的 faq_articlebody 可能包含 Markdown 图片或原始图片 URL。只要图片和答案步骤相关，就应按 ![Image Description](Image URL) 保留。

04 / Validation

迁移是否成功，必须用行为结果验证

实现规则写入 New Agent 后，验证不应只看配置是否保存，而要检查实际对话里的检索参数、答案引用和 fallback。

检查项 运行时判据 通过信号
域列表完整 问候语后主动读取 faq_topic.biz_groupname 并列出 7 个知识域。 GWM、GWM Test、HR、Lenovo IVA How-to、Lenovo IVA Troubleshooting、Power Platform、Test-LongH 全部出现。
首跳无 400 工具调用按约定传 organization=current，并把 options / entityParameters 作为 JSON 字符串传入。 无 Request validation 400，无 metadata 自纠重试。
引用不串域 选择 Lenovo 域后，答案生成前丢弃 biz_groupname 不匹配的检索记录。 References 和 Citations 不出现 Power Platform。
固定 fallback 无关问题或剩余上下文不直接回答问题时，不使用通用知识补答。 只返回固定句子；不附加解释、选项或 References。
