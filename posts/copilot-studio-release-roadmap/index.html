01 / 官方入口

用当前路线图查计划，用产品文档查实施条件

Release Planner 公告已停止更新，内容截至 2026-09-01，并计划在 2026-11-15 退役。Copilot Studio 产品选择会导向 AI at Work Roadmap；旧 Power Platform 发布计划已标为历史归档。[1][2][6]

公开预览（Public preview）供提前体验；一般可用（GA，General Availability）是正式发布阶段标签，不能省略后续的环境核验。[5][8]

入口适合回答不能据此推定
AI at Work Roadmap：Copilot Studio当前条目、原始状态、预计月份、云与平台标签。[2][3]精确部署日期；客户租户已经可用。
What's new in Copilot Studio按月查发布公告，保留 GA／Preview 原始标签。[5]当月第一天就是交付日；公告覆盖每一项功能。
能力专属 Microsoft Learn 文档具体操作、支持范围、前提与已知限制；如 Dataverse 的 15 表上限。[12]出现配置步骤就代表整个能力已经 GA。
Release Planner / Learn 历史计划追溯旧波次、原计划和启用方式。[1][6][7]旧波次仍在维护；过去的 GA 日期已经兑现。

先固定产品，再固定条目 ID，避免混入其他产品。harness 指负责模型调用与工具执行的运行时，不同 harness 的能力与计费可能不同。[20]

  1. 1
    从产品入口进入

    旧门户的实际产品参数是 app=Microsoft+Copilot+Studio；当前目标页的产品筛选是 Microsoft Copilot Studio。[1][2]

  2. 2
    保留 ID 和原文标题

    官方 RSS 给出逐条链接，例如 576272：新 harness 的网页浏览。同名条目不能只按标题合并。[3][4]

  3. 3
    同时打开实施文档

    条目没有文档链接时，需到 Learn 查对应能力；相近能力的文档不能当作同范围的交付证明。

02 / 状态解读

把目标日期、发布阶段与环境可用性分开

同一条记录可能写着过去的 GA 目标月份，却仍标为 In development。查询保留这两个事实，不按日历自动升级状态，也不把记录修改时间当作发布日期。[2][3]

路线图通常给到月份，发布公告通常给到月份标题；只有来源明确给出某天时，才保留日级精度。Learn 日期取自 HTML 的 ms.date 元数据，不是页脚 Last updated；未采集 updated_at，也不据任何日期升级发布状态。

字段或标记实际示例选型含义

过去的目标日期571305：两个目标月份均为 2026-10；仍 In development。[3]保留状态与月份的差异；没有变更说明时，不断言延期原因。
明确的发布标签2026 年 5 月公告：Computer use，(General availability)。[5]证明公告所指能力的阶段，不覆盖另一种 harness 或工具形态。
推出与来源元数据What's new 提醒更新会分多天推出。[5]ms.date 字段、开始推出与某个租户已经可用是不同判断。

General Availability、Preview、Targeted Release 等是路线图的发布阶段标签。Targeted release 如适用，Rollout start 表示它开始出现，随后才到 Standard release；这些标签不应改写成全量可用。[2][3]

      04 / 交付核验

      用目标环境的完整流程验证关键能力

      看见功能菜单只证明当前账户能看到入口。选型依据还需要同范围文档，以及授权测试数据在目标渠道、身份和权限下完成流程的结果；这里提供核验步骤，不声称已检测你的租户。

      568929 仍为开发中，但公告和实施文档已有可操作内容；结构化数据与预览中的非结构化列应分开验收。[3][5][12]

      1. 1
        固定要验收的数据范围

        先测试结构化表，最多 15 张表／知识源；Multiline Text 与 File 的非结构化检索另列预览依赖，不与普通表查询合并。[12]

      2. 2
        确认搜索与身份前提

        环境开启 Dataverse search，agent 使用 Authenticate with Microsoft；此知识源不支持 No authentication 或 Authenticate manually。底层权限不足会导致表不可选。[12]

      3. 3
        同时测允许和拒绝的数据

        建议用两名授权测试账户分别验证应能访问和不应访问的数据，比较答案、引用与拒绝结果。不要只测试 maker 的权限；这是建议的测试，不是已执行结果。

      4. 4
        发布后再测真实目标渠道

        预览列先设为 Searchable 并加入 Quick Find View；先加知识源后配置列可能最多需要两天回填。记录测试日期、配置与结果，再决定生产依赖。[12]

      保留环境范围、实施路径和可复现结果，避免以后只剩一个 GA 标签。

      条件应记录的内容
      租户、云与地区目标云／地区、环境与测试日期；本样本的 Worldwide 标签不证明每个云或租户均支持。[3][5]
      harness 与渠道运行时与网页、Teams 等部署渠道；不能跨范围套用发布结论。[9][11][20]
      语言与数据类型目标语言、文件／表类型和实际输入；未列出语言时，单独查文档与测试。[3][12]
      许可与计费前提对应许可、可用容量与测试／生产预算口径；共享 agent 的接收者文档有 per-user license 前提。[17][20]
      身份、连接与治理运行身份、连接权限与策略。SQL 依赖 maker 的连接与数据库权限；Entra Agent ID 不证明已具备独立邮箱。[13][19]
      端到端结果发布版本、目标渠道、允许／拒绝样例、错误与复测时间。SQL 文档建议先测已知小数据集的 diagnostic view。[13]

      05 / 选型判断

      把发布依据转成当前候选或有条件依赖

      计划适合跟踪方向；明确发布标签加同范围文档，适合启动验证；生产依赖还需要目标环境的验证结果。这是选型判据，不是对客户项目的验收结论。

      先写出采购必须满足的动作，再决定采用、试点或排除某项依赖；不按路线图日期给产品打分。

      1. 1
        当前方案候选

        有 GA 公告或 Launched 标记，加同范围实施说明。例如 standard Computer use 有 GA 公告和工具说明；仍需验证目标机器、身份与渠道。[5][9]

      2. 2
        试点／有条件依赖

        预览、推出中，或计划与实施说明有差异。REST evaluations 的 4 月公告是 Preview；standard harness API 文档要求 test set 与用户令牌，不能因已有 API 文档就升为 GA。[5][14]

      3. 3
        不写入当前交付承诺

        只有目标日期、条目取消，或范围不满足硬要求。例如 576272 新 harness 原生浏览仍开发中、562220 已取消；准备可用替代路径，分开未来能力与当前承诺。[3][9][11]

      要求越具体，越能看出相似名称之间是否真的可以替代。

      采购要求可查依据应采用的判断
      新 harness 本月原生浏览网页576272：2026-11 预览、2027-01 GA 目标，仍开发中；standard 工具另有 GA 公告。[3][5][11]不用 standard 的 GA 替新 harness 背书；验证现有路径或连接器替代，保留迁移条件。
      新分享界面直接给予编辑权限569475 为 Launched、描述有 Editor；现有文档说新界面只给 viewing rights，编辑需其他角色路径。[3][17]测试编辑、发布与角色分配；仅能查看／测试不足以满足协作编写要求。
      所有渠道按 IP 强制隔离历史计划有 GA 日期；现有文档仍为 preview，并不在 Teams／Microsoft Copilot 等渠道执行限制。[7][8]不作为全渠道隔离的唯一控制；另行满足安全要求。

      Agent Readiness 的路线图标记不能当作合规验收：相关 standard 文档仍为 preview，并说明状态摘要不替代管理员治理／合规报告。[3][18]

      快照用于稳定引用，官方实时页面用于确认变化；两者一起保留。

      1. 1
        按 ID 重开官方记录

        核对状态、月份、描述与实施范围。条目消失不证明已经交付：官方说明 GA、取消或推迟都可能导致信息移除。[2][4]

      2. 2
        以具体变更为准

        日期或描述改变时，保留前后版本与核对日期；没有官方说明时，不虚构延期、替代或撤回原因。

      3. 3
        保留未满足的选型条件

        写清 ID、官方依据、目标环境结果、剩余前提、替代路径与复查触发条件。旧 Planner 已停更，不作为当前计划的回退来源。[1]

      本页核对日期为 2026-11-09 UTC。RSS 当时的 lastBuildDate 为 2026-11-06 23:04:41 UTC；两者都不是功能交付日。[4] 可下载 功能快照 或查看 来源与支持范围；没有自动刷新或客户环境检测。
