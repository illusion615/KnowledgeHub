Project Delivery Within Governance

在既定治理边界内，把 Agent 从场景申请交付到持续运营

本指南面向业务 Owner、业务作者、项目交付团队和审批人。它不负责重新制定企业的 Zone、数据策略或环境规则；项目团队的任务是根据这些预置规则申请、构建、测试、发布和运营 Agent。

项目原则

项目不是制定治理规则，而是证明自己能够在规则内安全运行。

  • 1业务 Owner 提出场景和可验收结果
  • 2项目团队按既定 Zone 和环境要求交付
  • 3运行证据决定后续变更与扩展

01 / Delivery Boundary

先确认项目遵循哪套治理规则，再开始交付

企业治理体系预先规定哪些环境可用、哪些连接器和渠道可用、谁可以构建或发布，以及何时必须走更严格的流程。项目团队不自行放宽这些规则；遇到新需求时，向 CoE 或平台团队提交例外申请。[1][2]

环境

获分配的 Zone 与环境

确认项目被分配到个人 Developer 环境、专用开发环境，还是开发/测试/生产环境组合。

数据

批准的知识与连接

确认可使用的 Knowledge、Tool、HTTP、MCP、认证方式和发布渠道，不把未获批准的需求直接配置进 Agent。

责任

已指定的审批与支持路径

确认业务验收人、数据与安全审批人、发布审批人、Agent Owner 和运行支持联系人。

02 / Project Intake

业务 Owner 发起场景申请，项目团队据此完成准入

申请应说明业务任务、目标用户、预期渠道、人工接管、所需数据与集成、以及可接受的结果。CoE 用既定分区标准协调准入；平台、安全和数据团队只对超出既有边界的部分进行审查。[1]

  1. 01
    业务 Owner 提交场景

    发起人说明价值、用户、边界和结果，指定业务 Owner。

  2. 02
    CoE 完成分类

    根据既定 Zone、环境和申请标准确认适用路径，或将例外转交审批。

  3. 03
    控制 Owner 确认边界

    数据、安全和 IT Owner 对新增连接、敏感数据、对外渠道或关键集成作出批准或拒绝。

  4. 04
    平台管理员分配环境

    将作者加入批准环境并赋予所需角色；项目可在明确的配置边界内开始构建。

03 / Build

作者在获授权环境中构建，并把可部署内容纳入解决方案

业务作者或专业开发人员在分配的环境中配置 Agent 的 Knowledge、Topic、Action、Tool、认证与渠道。对于 Zone 2/3，项目团队应在 Solution 中管理可部署组件，使用环境变量和连接引用分离环境差异。[3]

执行：业务作者或专业开发负责 Agent 内容、动作和集成；业务 Owner 负责持续确认业务边界。支持：平台管理员处理环境与角色问题；数据、安全和 IT Owner 只审查变更中新增或超出既定边界的对象。

04 / Test

在测试环境用可重复证据验证 Agent 能否达到准入条件

业务作者建立 Test set，覆盖核心场景、知识问答、多轮对话、转人工、回归与对抗输入。项目团队还要在测试环境验证数据策略、角色、连接引用和生产知识源，再把结果提交给业务与发布审批人。[4]

发起与执行：作者维护 Test set；业务 Owner 定义验收结果；IT/专业开发验证集成与性能。批准：业务 Owner 签署业务验收；安全、合规和数据 Owner 确认高风险控制；发布审批人基于完整测试证据决定是否允许部署。

05 / Release

通过既定 ALM 路径把通过验收的 Agent 推进到生产

Zone 2/3 的发布应从开发环境经测试环境进入生产环境。项目团队使用 Solution、环境变量、连接引用和已选定的管道工具推进部署；认证、渠道、共享和 Application Insights 等不随 Solution 自动迁移的设置，应在下游环境按发布清单完成。[3]

执行：IT、专业开发或指定发布人员运行已批准的部署管道，并完成下游环境检查。批准：发布审批人确认测试、业务验收和高风险控制证据完整；业务 Owner 确认生产范围与支持路径；平台管理员确认目标环境已准备就绪。

06 / Operate

用运行证据管理已发布 Agent，而不是把上线当作终点

Agent Owner 在 Copilot Studio Analytics 中跟踪采用、会话结果和满意度；运营支持处理故障与转人工；平台团队关注容量、策略和安全状态。需要改变提示、Knowledge、连接、数据策略或发布范围时，项目回到既定的变更、测试和发布路径。[5]

01

修复与改进

Agent Owner 处理内容、知识和行为问题；超出既有边界的变更重新进入申请和审批。

02

扩展与加固

业务 Owner、CoE 和 IT 根据采用、质量、风险和成本，决定扩大用户范围、提高 Zone 或增加控制。

03

停止与归档

当场景失效或风险不可接受时，业务 Owner 申请停止；平台和数据 Owner 按企业留存与清理规则处理资产和记录。
