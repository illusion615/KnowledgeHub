## #requirements 01 / Design Requirements :: 文章图表必须同时满足可复现、可编辑、双语一致和静态发布 || Article Diagrams Must Be Reproducible, Editable, Bilingual, and Static at Runtime

Knowledge Hub 的一篇设计文章同时服务滚动阅读、全屏演示、PPT 导出和后续内容维护。图表如果只保存位图，无法可靠修改；如果只保存 Mermaid，复杂架构的图标、分组和连线路由受限；如果在页面运行 Draw.io，又会把编辑器依赖带给每位读者。因此首版用四项可验证要求约束方案。 || A Knowledge Hub design article serves scrolling, full-screen presentation, PPT export, and future maintenance. A bitmap alone cannot be edited reliably; Mermaid alone limits icons, grouping, and routing in complex architecture diagrams; running Draw.io on the page would impose an editor dependency on every reader. The initial design is therefore constrained by four testable requirements.

:::insight-grid { cols: 2, title: "四项要求共同定义可发布图表 || Four Requirements Define a Publishable Diagram" }
::card 01
### 确定性重建 || Deterministic Rebuild
在同一 Node.js 运行环境中，测试夹具连续编译两次必须产生字节一致的 SVG；跨运行环境一致性尚未纳入测试。 || Within the same Node.js runtime, compiling the test fixture twice must produce byte-identical SVG. Cross-runtime reproducibility is not yet tested.

::card 02
### 保留可编辑源 || Editable Source Retained
每张图必须提交标准 mxGraph XML 的 .drawio 文件；人工可以在 Draw.io 中继续调整，但语义变更仍回写 DiagramSpec。 || Every diagram commits a .drawio file containing standard mxGraph XML. Manual editing remains available, while semantic changes return to DiagramSpec.

::card 03
### 双语同源 || One Bilingual Source
节点标签必须提供 zh/en；边标签可以省略，但一旦提供也必须双语。缺少任一必需语言时编译直接失败。 || Node labels must provide zh and en. Edge labels are optional, but when present they must also be bilingual. Compilation fails when a required locale is missing.

::card 04
### 静态交付 || Static Delivery
文章只引用 SVG，保持 GitHub Pages 的零构建运行架构；Draw.io 和编译器只参与编辑期，不进入读者浏览器。 || Articles reference SVG only, preserving the zero-build GitHub Pages runtime. Draw.io and the compiler participate during authoring, not in the reader's browser.
:::

## #architecture 02 / System Architecture :: DiagramSpec 位于文章语义与发布资产之间 || DiagramSpec Sits Between Article Semantics and Published Assets

系统分为四个架构域：内容协作域定义读者问题和双语图意；Diagram Engine 承担规格校验、容器布局、几何检查和资产序列化；图表资产仓库保存可重建语义源、可编辑 Draw.io 和双语 SVG；Knowledge Hub 运行时只消费静态 SVG，分别服务阅读、演示与 PPT 导出。下图由 system-architecture.diagram.json 通过本设计的编译器生成。 || The system has four architecture domains. The content authoring plane defines the reader question and bilingual diagram intent. Diagram Engine owns specification validation, container layout, geometry checks, and asset serialization. The artifact store retains the rebuildable semantic source, editable Draw.io, and bilingual SVG. Knowledge Hub runtime consumes static SVG only for reading, presentation, and PPT export. The diagram below was generated from system-architecture.diagram.json by the compiler described here.

:::diagram { src: "./media/system-architecture", drawio: "./media/system-architecture.drawio", title: "Knowledge Hub 图表引擎系统架构 || Knowledge Hub Diagram Engine System Architecture" }
由 Diagram Engine 实际生成；SVG 是发布产物，Draw.io 是可编辑源文件。 || Generated by the Diagram Engine; SVG is the publication asset and Draw.io is the editable source.
:::

协作域只定义语义；引擎域独占几何计算和格式转换；资产域保存三类不同用途的文件；运行时域选择当前语言的 SVG，并交给现有灯箱、演示模式和 PPT 导出器处理。 || The authoring plane defines semantics only. The engine exclusively owns geometry and format conversion. The artifact store retains three files for distinct purposes. The runtime selects the active locale's SVG and delegates it to the lightbox, presentation mode, and PPT exporter.

| --- | --- | --- | --- |

| 编译器 || Compiler | DiagramSpec + 布局参数 || DiagramSpec plus layout parameters | Draw.io + 双语 SVG || Draw.io plus bilingual SVG | 改写文章论点 || Rewriting article claims |

## #contract 03 / Specification Contract :: DiagramSpec v1 只表达有向分层图 || DiagramSpec v1 Expresses Directed Layered Graphs Only

DiagramSpec v1 包含两套明确契约。architecture 与 flowchart 使用 nodes、edges 和 layer；architecture 还必须用 groups 表达真实系统边界。sequence 使用 participants 和按时间排序的 messages，消息可标记为 call 或 response。所有可见文本必须提供 zh/en，所有引用必须指向已声明实体。 || DiagramSpec v1 contains two explicit contracts. Architecture and flowchart use nodes, edges, and layer, while architecture must also use groups for real system boundaries. Sequence uses participants and time-ordered messages, with each message marked as call or response. All visible text must provide zh and en, and every reference must target a declared entity.

```
{
  "version": 1,
  "type": "flowchart",
  "title": { "zh": "编译流程", "en": "Compilation Flow" },
  "layout": { "direction": "right" },
  "nodes": [
    { "id": "spec", "layer": 0, "role": "artifact",
      "label": { "zh": "图表规格", "en": "Diagram Spec" } },
    { "id": "compiler", "layer": 1, "role": "service",
      "label": { "zh": "图表编译器", "en": "Diagram Compiler" } }
  ],
  "edges": [{ "from": "spec", "to": "compiler" }]
}
```

| 字段 || Field | 约束 || Constraint | 失败结果 || Failure Result |
| --- | --- | --- |
| `version` | 当前只能为 1 || Must currently equal 1 | 拒绝未知格式 || Reject unknown format |
| `nodes[].id` | 图内唯一 || Unique within the diagram | 编译终止 || Compilation stops |
| `label.zh/en` | 两个非空字符串 || Two non-empty strings | 禁止生成单语资产 || Prevent monolingual assets |
| `edges[].from/to` | 必须引用现有节点 || Must reference existing nodes | 报告未知节点 || Report unknown node |

:::callout { title: "关键洞察 || Key Insight" }
取舍：v1 不接受任意坐标、自由曲线和混合画布。这个限制牺牲自由度，换来可重复布局和可自动检查；需要任意绘图时仍可打开生成的 .drawio 文件人工编辑。 || Tradeoff: v1 does not accept arbitrary coordinates, free-form curves, or mixed canvases. The restriction trades freedom for reproducible layout and automated checks; arbitrary drawing remains available by opening the generated .drawio file.
:::

## #compiler 04 / Compiler Design :: 编译器用固定尺寸与分层坐标消除模型手算几何 || The Compiler Removes Model-Calculated Geometry with Fixed Dimensions and Layered Coordinates

图表编译器满足一个可复现需求：模型只提交语义关系，代码独占几何计算。编译器先按 layer 和 order 分组，再用画布边距、节点尺寸、层间距和同行间距计算坐标；横向图从左到右排列，纵向图从上到下排列；边使用源节点与目标节点边缘中点之间的正交折线。 || The compiler serves one reproducibility requirement: the model submits semantic relationships while code exclusively owns geometry. It groups nodes by layer and order, then calculates coordinates from canvas margins, node dimensions, inter-layer spacing, and within-layer spacing. Horizontal diagrams run left to right, vertical diagrams top to bottom, and edges use orthogonal paths between source and target edge midpoints.

| 阶段 || Stage | 机制 || Mechanism | 输出 || Output |
| --- | --- | --- |
| 验证 || Validate | 检查 schema、双语、角色、引用、循环和方向 || Check schema, locales, roles, references, cycles, and direction | 合法语义图 || Valid semantic graph |
| 布局 || Layout | 按 layer/order 分组并计算固定矩形；布局后逐对检测相交 || Group by layer and order, calculate fixed rectangles, then test every pair for intersection | 带坐标的中间模型 || Positioned intermediate model |
| 序列化 || Serialize | 中文和英文分别运行同一布局算法，再写入 mxGraph XML 与 SVG || Run the same layout algorithm for Chinese and English, then write mxGraph XML and SVG | 1 个 .drawio + 2 个 SVG || One .drawio plus two SVG files |

设计否决了让 AI 直接填写 x/y 坐标，因为同一语义会随模型和提示变化。架构图与流程图由容器、layer 和 order 决定几何；时序图由参与者顺序和消息顺序决定生命线与纵向位置。首版没有引入 ELK，采用外部布局器的判据是出现循环、嵌套容器或需要绕开障碍物的连接线。 || The design rejects AI-authored x/y coordinates because identical semantics can produce different geometry across models and prompts. Containers, layer, and order determine architecture and flow geometry; participant and message order determine sequence lifelines and vertical positions. The initial release does not use ELK. An external layout adapter becomes justified when cycles, nested containers, or obstacle-avoiding connectors appear.

:::callout { title: "关键洞察 || Key Insight" }
失败样例：横向画布只有 400px，却放置四层 210px 节点时，布局后矩形发生相交，编译器报告具体节点对并终止；它不会通过缩小字体掩盖错误。 || Failure example: when a 400px-wide horizontal canvas contains four layers of 210px nodes, rectangle intersection occurs after layout. The compiler reports the exact node pair and stops instead of hiding the error with smaller text.
:::

文字边界：v1 使用固定节点尺寸和单行 SVG 文本，尚未自动检测文字溢出。作者必须在浏览器中确认标签完整显示；过长内容应缩短标签、拆分节点或提高全图节点宽度。 || Text boundary: v1 uses fixed node dimensions and single-line SVG text, and does not yet detect text overflow automatically. Authors must confirm complete labels in the browser; longer content requires shorter labels, split nodes, or a wider diagram-wide node size.

An overlap-free SVG may still be too dense on mobile, shrink excessively in English, or intrude into presentation navigation. The workflow therefore validates DiagramSpec and geometry first, embeds candidate assets into the article, and then checks desktop, mobile, themes, and PPT in the real page. ## #quality 07 / Quality Gates :: 机器检查结构，人审查信息层级与阅读体验 || Automation Checks Structure; Reviewers Judge Hierarchy and Reading Experience

当前编译器检查版本、类型、方向、节点数量、ID、layer、角色、双语、边引用、自连接、循环与节点重叠。发布前必须检查五个具体组合：中文亮色桌面阅读、英文深色桌面阅读、英文深色手机阅读、中文亮色桌面演示、英文深色桌面演示。任何后续修改只要改变 DiagramSpec、编译器、图像容器或演示元数据，就必须使相应检查重新失效并重跑。 || The current compiler checks version, type, direction, node count, IDs, layers, roles, locales, edge references, self-connections, cycles, and node overlap. Before publication, five concrete combinations must pass: Chinese light desktop reading, English dark desktop reading, English dark mobile reading, Chinese light desktop presentation, and English dark desktop presentation. Any later change to DiagramSpec, the compiler, the image container, or presentation metadata invalidates the corresponding check and requires it to run again.

| 检查层 || Gate | 当前判据 || Current Criterion | 失败时处理 || Failure Handling |
| --- | --- | --- |
| Schema | 版本、类型、节点数、唯一 ID、layer、双语、边引用全部有效 || Version, type, node count, unique IDs, layers, locales, and edge references are valid | 停止编译并指出字段 || Stop compilation and report the field |
| 几何 || Geometry | 任意两个节点矩形不相交 || No two node rectangles intersect | 修改布局算法或规格层级 || Change the layout algorithm or specification layers |
| 发布 || Publication | 生成命令成功，人工确认每张图存在 .drawio、zh.svg、en.svg || The generation command succeeds and a reviewer confirms .drawio, zh.svg, and en.svg for every diagram | 禁止注册文章 || Do not register the article |
| 页面 || Page | 两种语言、亮暗主题、桌面与手机无截断或导航侵入 || No clipping or navigation intrusion across locales, themes, desktop, and mobile | 修编译器或图像容器后重测 || Fix the compiler or image container, then retest |

取舍：质量闸门不采用整图像素快照作为唯一自动判据，因为字体渲染、主题和浏览器差异会产生与信息质量无关的变化。结构错误由代码阻断，页面上下文由五个具体组合人工验收；如果标签在英文深色演示页被截断，先修规格或节点宽度，再重跑结构检查和受影响页面。 || Tradeoff: the quality gate does not use whole-image pixel snapshots as its only automated criterion because font rendering, themes, and browsers create changes unrelated to information quality. Code blocks structural errors, while five concrete manual combinations cover page context. If a label is clipped in the English dark presentation, fix the specification or node width, then rerun structural checks and the affected page state.

## #boundary 08 / Boundary and Evolution :: 首版覆盖重复需求，复杂拓扑再接入 Draw.io 官方布局 || The Initial Release Covers Repeated Needs; Complex Topologies Can Add Official Draw.io Layouts

本次实现已经完成规格验证、顶层架构容器、横向和纵向分层流程、时序生命线与消息、正交连接、Draw.io XML、双语 SVG 与文章嵌入。它不处理循环图、嵌套容器、云厂商图标和连接线避障。Draw.io Embed 可以调用 JSON Layout Specification 定义的布局并负责 SVG 导出；布局规范分别提供 ELK layered/tree/radial/organic 和独立的 orthogonalEdge/libavoid 避障路由，可在这些需求真实出现时作为几何适配器接入。[1][2] || This implementation completes specification validation, top-level architecture containers, horizontal and vertical layered flows, sequence lifelines and messages, orthogonal connectors, Draw.io XML, bilingual SVG, and article embedding. It does not handle cyclic graphs, nested containers, cloud-provider icons, or obstacle-avoiding routes. Draw.io Embed can invoke layouts defined by the JSON Layout Specification and perform SVG export. The layout specification separately provides ELK layered, tree, radial, and organic layouts and the orthogonalEdge/libavoid obstacle router; these can become a geometry adapter when those needs appear.[1][2]

| 能力 || Capability | 状态 || Status | 采用判据 || Adoption Criterion |
| --- | --- | --- |
| 架构、流程与时序图 || Architecture, flow, and sequence diagrams | 已实现 || Implemented | 容器化架构、有向分层流程或按消息排序的模块交互 || Container architecture, directed layered flow, or message-ordered module interaction |
| Draw.io 人工编辑 || Manual Draw.io editing | 已实现 || Implemented | 打开生成的 .drawio 文件 || Open the generated .drawio file |
| ELK 自动布局 || ELK automatic layout | 按需接入 || Demand-Driven | 出现循环图、复合图或三层以上分支 || Cyclic, compound, or deeply branching graphs appear |
| libavoid 连线避障 || libavoid edge routing | 按需接入 || Demand-Driven | 自动检查发现连接线穿越非目标节点 || Automated checks detect connectors crossing unrelated nodes |
| Next AI Draw.io 应用 || Next AI Draw.io application | 不引入 || Not Adopted | AI 编排已由内容协作 Agent 提供，无需第二套聊天与模型配置 || The content agent already provides AI orchestration, so a second chat and model configuration is unnecessary |

:::callout { title: "关键洞察 || Key Insight" }
选择标准：新增图表类型必须由至少一篇真实文章提出，并且无法由现有 flow-list、Mermaid、数据 SVG 或 DiagramSpec v1 清晰表达；否则不扩展引擎。 || Extension criterion: a new diagram type must be required by a real article and cannot be expressed clearly by the existing flow list, Mermaid, data SVG, or DiagramSpec v1. Otherwise, the engine does not expand.
:::
