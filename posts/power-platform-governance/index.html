A.

3 Containers — Where Everything Lives

A strict three-level hierarchy. Resources never leak across these boundaries unless an admin explicitly bridges them with connectors or DLP exceptions.

1. Tenant — the Microsoft Entra ID boundary

Your organization's identity perimeter. One tenant = one organization. All Power Platform resources live inside it; tenant-level admins (Global, Power Platform, Dynamics 365) hold the highest authority.

▼

2. Environment — the isolation & governance boundary

A regional container holding apps, flows, connections, gateways, and optionally a Dataverse database. Resources in one environment cannot read another. This is where DLP policies, capacity, and access roles are scoped.

▼

3. Dataverse — the in-environment data store

Optional cloud relational database inside an environment. Decided at environment creation time. When present, it adds its own security-role layer (table + column + row-level) on top of environment access.

B.

Management Surface — What You Configure at Each Level

For each container, the cards below list the management features that actually live there and the role required to operate them. Use this to answer "where do I go to change X?" without searching the docs.

Tenant level

Tenant settings & tenant-wide policies

Management features

  • Tenant settings (sharing, search, telemetry, support)
  • Environment creation policy and quotas
  • Tenant-wide DLP / data policies
  • Tenant capacity pool and add-ons
  • Managed Environments enrollment
  • Self-service signup and trial controls
  • Tenant analytics, audit, and CoE views
  • Pay-as-you-go billing plan registration

Required role: Global Administrator, Power Platform Administrator, or Dynamics 365 Administrator.

Environment level

Per-environment configuration

Management features

  • Environment type, region, and security group binding
  • Capacity allocation from the tenant pool
  • Environment-level DLP exceptions
  • Backup, restore, copy, reset, delete
  • Dataverse provisioning toggle
  • Connector and connection settings
  • Managed Environments features (sharing limits, solution checker, IP firewall, CMK, Lockbox)
  • Environment analytics and usage views

Required role: Environment Admin (full control); Environment Maker can build inside the environment but cannot administer it.

Dataverse level

Data, schema, and per-record security

Management features

  • Tables, columns, relationships, choices
  • Business units and teams
  • Security roles, role assignment, hierarchies
  • Row-level access modes (User / BU / Parent: Child BU / Org)
  • Sharing and assignment rules
  • Auditing and field-level security
  • Plug-ins, processes, and customizations

Required role: System Administrator (within the environment) for full control; System Customizer for schema; custom Dataverse roles for scoped data work.

C.

3 Permission Layers — Who Can Operate Each Layer

The three management surfaces in B map to three permission layers. Access is checked top-down: an action only succeeds when the user clears the layer that owns the surface they're touching.

Layer 1

Tenant Admin Roles

Microsoft Entra roles: Global Administrator, Power Platform Administrator, Dynamics 365 Administrator. Cross-environment authority — create environments, set tenant DLP, manage capacity, enroll Managed Environments.

Layer 2

Environment Roles

Environment Admin (full control of one environment) and Environment Maker (build apps and flows, no admin actions). Scoped to a single environment only and does not grant Dataverse data access.

Layer 3

Dataverse Security Roles

Granular table + column + record-level privileges (Create, Read, Write, Delete, Append, Share). Built-ins: System Administrator, System Customizer, Basic User. Only present when an environment has Dataverse.

D.

2 Admin Centers — Where You Actually Click

Two consoles, two responsibilities. Knowing which one owns a setting saves hours of search-engine spelunking.

admin.microsoft.com

Microsoft 365 Admin Center

Identity-side: buy & assign user licenses, manage users and groups, enable/disable self-service signup, view tenant-wide service health. Run by your M365 / identity team.

admin.powerplatform.microsoft.com

Power Platform Admin Center

Workload-side: create environments, allocate capacity, configure DLP policies, manage tenant settings, run analytics, set up Managed Environments. Run by your Power Platform admin / CoE team.

04 / Capacity Allocation

Turn Tenant Dataverse Entitlement Into Per-Environment Operating Budgets

Now that you know what you've licensed (§02) and where it lives (§03), Dataverse storage is the first resource that needs intentional budgeting. Every tenant receives a pool (database + file + log) based on licenses purchased; effective governance means allocating it per environment and monitoring continuously.

01

Three storage types

Database — table rows, metadata. File — attachments, images. Log — audit logs, plugin traces. Each has its own pool.

02

Capacity sources

Tenant default (at sign-up) + per-user license accruals + add-on purchases. Check Licensing > Capacity add-ons in admin center.

03

Allocate per environment

Admins can preallocate capacity from the tenant pool to specific environments. Set daily email alerts when consumption hits a threshold.

04

Overage enforcement

15% remaining: first warning. 5%: ops impact warning. In overage: create/copy/restore blocked. Default env has its own 3+3+1 GB quota.

Source: Dataverse capacity-based storage details.

05 / Environment Strategy

Choose the Right Environment Type for Each Workload — Default, Sandbox, or ALM-Ready Production

Capacity (§04) lives inside environments. Environments are the primary governance boundary — each is scoped to a region and optionally contains Dataverse. Pick the right type up front; converting later is painful or impossible (e.g. the "Enable Dynamics 365 apps" switch is set at provisioning time and can't be reversed).

Core

Default

One per tenant, auto-created. All licensed users get Maker role. Limited to 1 TB. Cannot be deleted. Designed for personal productivity — NOT production. Rename it to clarify purpose.

Managed

Production

Full admin control. For permanent, business-critical workloads. Requires 1 GB available capacity. Full backup & restore support.

Dev/Test

Sandbox

Non-production with copy & reset. For development and testing. Full admin control. Convert to/from production.

Temporary

Trial

Expires after 30 days. One per user. Admin-controlled creation. Cannot enable Dynamics 365 apps.

Temporary

Developer

Via Developer Plan. Individual-use only, no sharing. No security group assignment. For learning and prototyping.

Auto

Dataverse for Teams

Auto-created when a Power App is first built in Teams. Limited admin settings. Roles map to Teams membership automatically.

1. License eligibility — Power Apps/Automate/D365 plan required. M365, Teams, and Developer Plan do NOT grant creation rights. Waived for PP and D365 admins.

2. Available capacity — Tenant must have at least 1 GB available database storage.

3. Tenant policy — Admin must not have restricted environment creation via tenant settings.

Important: The "Enable Dynamics 365 apps" setting is chosen at database provisioning time and cannot be changed later.

1–10 users, non-confidential, no ALM → Default environment.

7–30 users, confidential data, or needs ALM → Shared production with security group.

>30 users, monetary/reputational impact → Dedicated production with its own ALM pipeline.

Always bind a security group to production and sandbox environments.

Sources: Environment types, Create environments, Manage default environment.

06 / Permission Assignment

Grant the Minimum Permission at Each of Three Layers — Never One-Shot 'Admin' Anywhere

Once environments (§05) exist, you put people into them — but at three independent layers. Granting someone an environment role does NOT automatically give them data access. Each layer serves a distinct purpose; mix them up and you either over-share or block legitimate users.

Layer 1: Tenant Admin Roles

Assigned in Microsoft Entra ID or M365 admin center. Controls who can govern the platform across all environments.

Global Administrator Power Platform Administrator Dynamics 365 Administrator
▼

Layer 2: Environment Roles

Assigned in Power Platform admin center. Controls who can build and administer resources. Does NOT grant data access in Dataverse tables.

Environment Admin Environment Maker
▼

Layer 3: Dataverse Security Roles

Assigned in PP admin center > Environment > Settings > Users + Permissions. Controls data privileges with table-level actions (Create / Read / Write / Delete / Assign / Share) at four access levels.

System Administrator Basic User App Opener Custom Roles

The five Entra roles below are the ones IT teams most often confuse when wiring up Power Platform. Assign the narrowest role that satisfies the duty — Global Administrator should be the break-glass exception, not the default.

Entra role Manage PP environments & DLP Assign user licenses Manage users / groups / MFA Manage all other M365 services Typical owner
Global Administrator Yes Yes Yes Yes Break-glass account only (2–4 named owners, MFA + PIM)
Power Platform Administrator Yes — full control of every environment, DLP policy, capacity, tenant settings No No No Power Platform CoE / platform ops lead
Dynamics 365 Administrator Yes — same scope as Power Platform Administrator across all environments No No No Legacy / D365-first orgs; treat as equivalent to Power Platform Admin today

07 / Monitoring and Governance Controls

Stop Bad Actions With DLP and Managed Environments — Then Watch the Signals in Power Platform admin center

Permissions (§06) decide who can act. Governance controls decide what those actions are allowed to touch — and how you spot misuse early. Run governance as a closed loop: define policy, enforce, monitor, remediate.

Preventive

Data Policies (DLP)

Classify connectors into Business / Non-Business / Blocked groups. Connectors in different groups cannot coexist in one app or flow. Enforcement latency: typically <1 hour, up to 24h at scale. Violations cause apps/flows to be suspended.

Premium

Managed Environments

Adds sharing limits, usage insights, extended backup, solution checker, IP firewall, Customer Managed Key, and Lockbox. Included with standalone PP/D365 licenses. Not included with Developer Plan.

Monitoring

Admin Center Views

Inventory — all apps/flows/agents. Usage — adoption tracking. Monitor — operational health. Actions — risks & recommendations. Replaces CoE Starter Kit as primary governance tool.

Network

Conditional Access & Intune

Entra ID P1/P2 conditional access policies for Power Apps/Automate based on user, device, or location. Intune mobile app protection on iOS/Android.

Sources: Data policies, Managed Environments, CoE Starter Kit transition.
