Microsoft Business AI Solution · Strategic Overview

Agentic CRM：以业务周期为中心重构客户经营

客户经历的是连续的价值周期，企业却常用分散的营销、销售、交付和服务系统承接它。AI 时代的 CRM 不应继续以应用边界和记录维护为中心，而应围绕业务目标持续感知信号、形成判断、协同人与 Agent、执行动作并从结果中学习。本方案以 Microsoft Business Applications 为业务主干，以 Microsoft 365 与 Work IQ 连接日常工作，以 Microsoft Foundry 和 Azure AI 支撑复杂智能与企业治理。

核心主张

CRM 的下一代形态，是 AI 运营、人工负责的业务周期系统。

记录仍然重要，但记录不再是终点。Agentic CRM 把客户信号、工作上下文、业务规则和系统动作连接成持续运行的周期；人负责目标、关系、判断和高风险例外，Agent 承担规模化感知、分析、协调与执行。

  • 2系统角色：从被动记录转向持续感知、判断与行动
  • 3工作组织：从跨部门串行交接转向人与 Agent 并行协同
  • 4治理方式：从上线审批转向持续评估、观察与自治分级

01 / 重新定义 CRM

CRM 的边界应由客户价值周期定义，而不是由软件菜单定义

传统 CRM 通常围绕营销、销售和客服模块组织，优化对象是记录、阶段和任务。客户经营的实际结果却跨越市场信号、商务承诺、履约、采用、服务与续约。Agentic CRM 以完整周期为对象，重新分配人与系统的责任，并把每次互动转化为下一步行动。

传统 CRM

围绕记录和职能边界运行

  • 1用户进入系统寻找页面、记录和字段
  • 2流程由部门交接和预设顺序驱动
  • 3洞察多在事后报表中呈现
  • 4自动化优化单个步骤，整体周期保持不变
Agentic CRM

围绕业务结果和连续周期运行

  • 1用户表达目标，Agent 组织所需知识、流程和工具
  • 2流程根据客户行为、风险与上下文动态调整
  • 3洞察在决策时点直接转化为可执行动作
  • 4人与 Agent 并行协同，高风险判断仍由人负责
定义 本文将 Agentic CRM 定义为：以客户价值周期为运行单元，由 Agent 持续感知信号、理解上下文、组织决策与执行，并由人承担目标设定、关系经营、重大判断和结果责任的企业业务系统。

02 / 最新理念与事件

2024–2026 的信号共同指向：从单点 Copilot 转向业务流程重构

这一判断不是概念推演。微软产品路线、全球工作趋势和企业 AI 调研都显示：Agent 已进入业务应用和协作入口，但企业级价值仍取决于是否重构工作流、明确人与 Agent 的责任，并建立可规模化治理。

  1. 2024-10 · Dynamics 365 引入 10 个自主 Agent

    微软宣布 Sales Qualification、Customer Intent、Customer Knowledge Management 等 Agent，并将 Agent 描述为 AI 时代的新应用形态，覆盖销售、服务、财务与供应链流程。[1]

  2. 2025-04 · Work Trend Index 提出 Frontier Firm

    微软基于 31,000 名知识工作者调查、LinkedIn 数据和 Microsoft 365 遥测提出 AI-operated but human-led 组织。82% 的领导者认为当年应重新思考战略与运营，81% 预计未来 12–18 个月中度或广泛整合 Agent。[2]

  3. 2025-11 · 广泛采用尚未转化为普遍企业收益

    McKinsey 对 1,993 名受访者的调查显示，88% 的组织在至少一个职能常态使用 AI，但只有 39% 报告任何企业层 EBIT 影响；23% 正在某个职能规模化 Agent。高绩效组织更常重构工作流，而不只部署工具。[3]

  4. 2026-04 · Microsoft 业务应用进入 Agentic Wave

    Dynamics 365 2026 Wave 1 将 Sales 描述为从记录系统走向行动系统；Customer Insights - Data 成为 CRM Agent 的 grounding layer；Journeys 跨营销、销售和服务编排；Field Service 推进 Scheduling Operations Agent。Power Platform 同期加强 Agent、Dataverse、Work IQ 与治理。[4][5]

不同研究的样本、对象和指标并不相同，数字只用于说明采用、规模化和价值之间存在明显落差，不能直接作为某一企业的收益预测。

03 / 传统 CRM 的业务断点

业务结果在交接处损失，而传统 CRM 主要记录交接后的状态

企业已经积累大量客户数据、流程和报表，但周期仍被部门、系统和角色切开。问题不在于少一个字段或少一张看板，而在于信号无法连续变成判断，判断无法连续变成跨团队行动，行动结果也没有及时回到下一轮经营。

01

信号断点

邮件、会议、网页行为、服务记录、设备事件和外部变化分散在不同位置。大量信号没有进入 CRM，进入后也常缺少时间、关系和业务语境。

02

决策断点

优先级、风险、下一步和资源配置依赖人工汇总与经验。报表解释过去，却很少在关键时点组织证据、备选方案与可执行建议。

03

执行断点

一次客户需求可能跨越营销、销售、合同、供应链、项目和服务。串行交接、重复录入和缺少闭环责任造成周期延迟和客户体验不一致。

04

学习断点

赢单、流失、延期、返工、投诉与续约结果没有系统地回写到分群、评分、话术、流程和 Agent 评估中，组织重复经历同类问题。

04 / 六阶段业务周期

以客户价值演进为主线，连接获客、承诺、履约、服务与增长

Agentic CRM 不要求企业用一个系统替代所有应用，而要求所有应用围绕同一周期共享目标、信号、状态和责任。六个阶段不是固定部门，而是客户价值从需求出现到持续增长的连续演进。

01

感知需求

汇集市场变化、数字行为、客户关系、产品使用、服务事件和外部信号，识别需求形成、风险变化与最佳互动时点。

02

互动与识别

围绕客户意图组织个性化互动，持续研究、澄清和评估价值匹配，避免把所有信号都转成人工跟进或低质量线索。

03

方案与承诺

把客户需求、产品能力、价格、合同、风险和交付条件组织成可验证承诺；人负责关系、谈判和重大取舍，Agent 负责证据和协同。

04

履约与采用

连接订单、项目、供应链、交付、培训和使用行为，让商务承诺转化为客户可感知的结果，并提前识别延期、范围和采用风险。

05

服务与恢复

跨自助、联络中心和现场服务识别意图、组织知识、协调资源和解决问题；对高风险、情感和例外场景及时转交人员。

06

续约与增长

依据使用、价值实现、关系健康、服务历史和外部变化判断续约风险与扩展机会，把服务结果重新送回营销和销售。

周期责任 每个阶段都必须定义业务结果、周期责任人、客户可感知的完成条件、Agent 自治范围和下一阶段所需的最小上下文。没有这些定义，跨应用集成只会把更多数据连接在一起，而不会形成业务闭环。

05 / 六种运行能力

Agentic CRM 通过六种能力持续运行，而不是等待用户打开系统

业务周期回答了经营对象是什么；六种能力回答系统如何运转。它们贯穿所有阶段，并根据风险选择规则、分析模型、生成式 AI 或 Agent，不把每项任务都强行 Agent 化。

01

感知

监听业务事件、客户行为、邮件会议、服务与设备信号，并判断哪些变化值得进入当前业务周期。稳定阈值用规则，复杂模式用分析模型。

02

理解

把结构化记录、文档、对话、图像和历史关系组合成当前语境，区分事实、推断与未知项，并保留来源和权限。

03

决策

依据业务目标、风险、客户偏好和资源约束生成可选方案、优先级和下一步。高风险决定必须由确定性规则或人批准。

04

协同

让人员、Agent、流程和系统并行工作，组织输入输出、依赖、升级和例外，而不要求用户理解所有应用和接口。

05

执行

在授权范围内更新记录、触发流程、生成材料、安排任务和沟通客户。不可逆动作使用确认、审批、幂等和回滚控制。

06

学习

把接受、编辑、拒绝、结果和例外转化为流程、知识、模型和 Agent 评估的反馈，使周期随业务变化持续改进。

06 / 人与 Agent 的责任

自治程度由业务风险和可逆性决定，而不是由模型能力决定

Agent 能做什么不等于企业应该允许它做什么。每个周期阶段都需要显式划分自动执行、会话内确认、离线审批和人工主导四类责任，并在目标、权限、证据和升级路径上保持一致。

L1

建议

Agent 读取、研究、摘要和提出选项，人决定是否采取行动。适用于新场景、高不确定性和关系导向工作。

L2

起草并确认

Agent 生成记录、内容、计划或流程草稿，用户确认、编辑或拒绝后执行。适用于中风险、高频业务动作。

L3

受控自治

Agent 在金额、对象、时间和权限边界内自动执行，并对异常、低置信和敏感情形升级。适用于成熟且可观察的流程。

L4

人工主导

人主导关系、谈判、重大承诺、伦理与监管判断；Agent 仅提供证据、模拟和行政支持。最终责任不可转移。

Agent 不是默认答案。低变化、高标准化、要求完全重复的任务优先使用业务规则、Power Automate 或分析模型；只有需要理解开放语境、跨系统协调和动态适应时，Agent 才增加价值。[6]

工作特征优先机制CRM 示例
固定条件与固定结果规则与流程自动化信用阈值、审批路由、SLA 计时、必填校验
大量历史数据中的模式判断预测与分析模型流失风险、需求预测、线索评分、库存预测
开放语境、跨系统、多步骤与例外Agent 与编排客户研究、方案协同、复杂服务恢复、续约策略
重大关系、承诺、监管与伦理判断人工主导，AI 支持合同谈判、重大赔付、客户冲突、受监管决策

07 / 微软全栈总览

微软优势来自业务、工作与智能三层共享同一身份、数据和治理体系

Agentic CRM 需要同时理解业务记录、日常工作与复杂非结构化内容，并能够在安全边界内执行。微软的全栈价值不在于产品数量，而在于 BizApps、Modern Work 与 Azure 可以在 Entra、Dataverse、Microsoft Graph、Work IQ 和统一治理下协同。

业务主干

Microsoft Business Applications

Dynamics 365、Power Platform 和 Dataverse 提供客户、产品、交易、流程、规则和行业扩展，是业务语义与最终记录的主干。

工作上下文

Microsoft 365 与 Modern Work

Outlook、Teams、SharePoint、OneDrive、Copilot 与 Work IQ 提供邮件、会议、文档、关系和组织语境，让 Agent 在用户实际工作位置出现。

高级智能

Microsoft Foundry 与 Azure AI

提供多模型、复杂 Agent、企业知识、文档与语音理解、私有网络、身份、评估和可观测，用于超出标准 BizApps Agent 的战略能力。

全栈设计原则 优先使用最接近业务责任和用户工作位置的能力：标准业务流程优先 BizApps，工作语境和员工入口优先 Microsoft 365，复杂模型、专有智能和高级运行时再使用 Azure。全栈不等于所有产品同时上场，而是用统一身份、权限和治理选择最合适的层。

08 / BizApps 业务主干

BizApps 为 Agent 提供可执行的业务语义，而不只是数据接口

Agent 若只连接数据，仍需自行理解客户、机会、订单、项目、资产、工单和财务责任。Dynamics 365 与 Power Platform 提供成熟业务对象、流程、规则和角色，使 Agent 能在企业已经认可的责任结构中行动。

01

客户与旅程

Customer Insights - Data 统一客户档案和行为信号，为 Agent 提供可靠 grounding；Journeys 根据行为和上下文跨营销、销售与服务调整互动。[4]

02

销售与商务

Dynamics 365 Sales 覆盖研究、识别、机会、关系、预测和销售执行。2026 Wave 1 明确将其从记录系统推进为持续丰富数据、分析信号和优先行动的行动系统。[7]

03

服务与履约

Customer Service、Contact Center 和 Field Service 连接意图、知识、渠道、SLA、调度、资产与现场执行；Field Service 进一步连接 Finance、Supply Chain 和 Project Operations。[4][8]

04

扩展与自动化

Power Apps 承载角色化体验，Power Automate 连接流程与桌面操作，Copilot Studio 编排知识、工具和 Agent，Dataverse 提供业务数据、权限、审计和 ALM。

官方计划覆盖 2026 年 4–9 月，并明确功能时间可能变化或不发布。战略设计可以采用产品方向，实施设计必须逐项核验区域、许可、预览状态、开启方式和依赖条件。

09 / Modern Work 上下文

客户经营发生在 Outlook、Teams、会议和文档中，Agent 必须进入工作现场

CRM 记录只包含客户经营的一部分。邮件承诺、会议异议、内部协作、方案文档和组织关系存在 Microsoft 365 中。Modern Work 的职责是补足工作语境，并让业务 Agent 出现在用户日常工作入口，而不是迫使用户频繁切换系统。

01

工作语境

Work IQ 在现有权限和敏感度标签下组合邮件、会议、文档、Teams 消息、人员关系和工作模式，为 Agent 提供用户当前工作的语境。[9]

02

协作入口

Microsoft 365 Copilot、Teams 和 Outlook 让销售、服务和管理 Agent 在邮件、会议、聊天与工作台中使用；Sales agent 已能把 CRM 洞察带入 Outlook 与 Teams。[10]

03

企业知识

SharePoint 与 OneDrive 承载方案、政策、产品、合同模板和服务知识；Copilot connectors 可以同步外部内容，也可以通过 MCP 实时读取而不复制到 Microsoft Graph。

04

会议到行动

Teams 会议洞察、行动项和 @提及可以进入客户周期，生成后续、风险和协作任务；业务系统继续保存最终承诺和交易状态。

权限边界 工作上下文不能成为扩大数据访问的旁路。Work IQ 请求在已登录用户上下文中运行，遵守 Microsoft 365 权限和敏感度标签；业务 Agent 也必须在业务系统权限下读取和执行。汇总层不得泄露用户原本看不到的记录。

10 / Azure 高级智能

Azure 用于标准 BizApps 能力之外的复杂智能、专有知识和生产级治理

标准销售、旅程、服务和自动化能力优先使用 BizApps。只有当企业需要自有模型策略、复杂多 Agent、专有文档与多模态理解、私有网络或高级评估时，才引入 Microsoft Foundry 和 Azure AI，避免为技术先进性增加无必要复杂度。

01

模型与复杂 Agent

Microsoft Foundry 提供多模型目录、prompt agent、Hosted agent、Responses API 和自定义编排，适用于复杂逻辑、多 Agent 与专有协议。[11]

02

企业知识与内容

Azure AI Search 可在权限控制下组合全文、向量、混合与多模态检索；Document Intelligence 将合同、发票、表单和自定义文档转为结构化业务内容。[12][13]

03

身份、安全与网络

Foundry Agent Service 提供专用 Entra Agent identity、RBAC、内容过滤、私有网络和数据驻留控制，使 Agent 使用范围明确的身份访问工具与数据。

04

评估与可观测

Tracing、评估、版本、监控与 Application Insights 记录模型调用、工具执行和决策路径，支持回归测试、成本分析和生产问题定位。

选择依据是业务差异化与运行要求，不是团队偏好的开发工具。能够由标准业务 Agent 和平台流程稳定满足的场景留在 BizApps；只有明确的专有智能或运行约束才进入 Azure。

11 / 已落地实践

Sales Mobile 与 Service Mobile 验证同一理念在不同周期阶段的落地

Agentic CRM 总览定义企业级周期、责任与平台边界。Agentic Sales Mobile 和 Agentic Service Mobile 是这一框架下的两项实践：它们不代表全部 CRM，而是分别验证销售互动和现场服务如何从记录负担转向即时行动。

实践 01 · Agentic Sales Mobile

从销售录入工具到即时决策伙伴

覆盖互动识别、方案承诺和增长环节。移动端以今日大盘、访前背景、语音拜访录入、商机草稿和下一步建议为核心，让销售在贡献数据的当下获得回报。

  • 1输入：语音、会议、邮件与客户互动
  • 2输出：客户活动、商机草稿、风险与下一步
  • 3责任：销售确认关键写入并主导关系与承诺
查看 Sales Mobile 实践
实践 02 · Agentic Service Mobile

从数百字段工单到持续服务采集

覆盖履约采用、服务恢复和增长反馈。移动端用 SLA 顺序、访前简报、持续语音问卷、完成确认与受控主数据变更，让现场人员专注解决问题。

  • 1输入：工单、资产、语音、照片、条码与客户陈述
  • 2输出：工单草稿、缺失项、主数据申请与复查任务
  • 3责任：现场人员确认事实，数据管理员审批主数据变化
查看 Service Mobile 实践
实践复用原则 两项实践复用同一套责任分级、确认模式、可追溯输出、数据分域和 Agent 运营方法。新场景应优先复用这些模式，而不是为每个部门重新创建一套 Agent、连接器和治理。

12 / 跨周期示例

一次服务事件如何转化为客户恢复、续约保护与增长机会

业务周期的价值体现在跨阶段闭环。下面用一个设备服务事件说明：信号如何被识别、如何协调服务与供应链、如何保护客户关系，并在客户确认价值后形成合理的续约与扩展动作。

  1. 1 · 感知异常

    设备事件、重复服务记录和客户邮件共同显示同一站点存在持续性能下降；规则确认达到服务触发条件。

  2. 2 · 组织背景

    Service Agent 汇总资产、历史工单、SLA、备件和联系人；Work IQ 补充最近会议承诺，所有事实链接来源。

  3. 3 · 协同执行

    Scheduling Agent 匹配技能、位置和承诺时间，供应链流程预留备件，现场人员收到移动工单与访前策略。

  4. 4 · 透明沟通

    客户在首选渠道收到到达时间、处理计划和进展；重大承诺和补偿方案由服务经理批准后发送。

  1. 5 · 确认恢复

    现场服务记录、设备信号和客户确认共同证明问题解决；工单关闭条件和 SLA 结果由确定性规则计算。

  2. 6 · 更新关系风险

    客户健康模型吸收事件严重度、恢复速度、沟通反馈和使用恢复情况；Agent 说明风险变化依据，不把单次成功直接等同于关系修复。

  3. 7 · 保护续约

    若合同临近续约，Customer Success 与销售收到事实简报、未完成承诺和客户反馈，优先解决价值缺口而非立即推销。

  4. 8 · 识别合理增长

    只有当使用、结果和客户意图支持时，系统才起草扩容、维保或升级机会，并把服务证据带入销售对话，由客户负责人决定是否推进。

客户信任原则 服务事件不能被机械地转化为销售线索。恢复客户结果和履行承诺优先于增长；只有在客户价值已经恢复、意图明确且人员判断适当时，增长动作才进入下一阶段。

13 / 价值指标

价值衡量从使用率和记录完整率，升级为周期速度、客户结果与可信自治

Agentic CRM 的价值不能只用节省工时衡量。它同时改变增长速度、履约质量、服务恢复、员工容量和风险结构。企业应为每个优先周期建立基线、目标、守护指标和财务兑现路径，避免单项效率改善转移成本。

01

周期速度

线索到合格、需求到方案、承诺到履约、问题到恢复、采用到续约的端到端时间，以及等待、返工和交接占比。

02

增长与关系

高质量机会转化、赢单速度、采用、续约、扩展、关系覆盖和客户价值实现，不把互动数量直接视为增长。

03

服务与运营

首次解决、SLA、停机时间、履约偏差、现场人员容量、知识复用和成本到结果，而不只计算自动化步骤数量。

04

信任与治理

建议采纳与编辑、未经确认写入、越权调用、错误升级、来源覆盖、评估通过率、单位结果成本和 Agent 退役率。

周期主指标守护指标财务兑现
互动与识别合格机会速度与转化误判、退订、低质量线索与人工复核销售容量与高质量管道增量
方案与承诺需求到可交付承诺时间合同偏差、毛利风险与审批例外赢单周期、方案成本与毛利保护
履约与服务承诺达成、首次解决与恢复时间返工、客户升级、未经确认动作与安全事件履约成本、赔付规避与现场容量
续约与增长价值实现、续约和合理扩展不当推销、关系风险与流失原因留存收入、扩展收入与流失规避

14 / 治理与运营模型

治理对象从应用和模型，扩展为业务周期、Agent 职责和运行结果

Agent 能够主动、持续和跨系统行动，传统的一次性上线审批不足以覆盖其风险。企业需要同时治理周期目标、Agent 目录、自治权限、数据使用、评估、成本和退役，并由业务负责人而非单一技术团队承担结果责任。

01

业务周期责任人

定义周期结果、客户完成条件、主指标、守护指标和跨团队责任；决定哪些工作需要重构、自动化或保持人工主导。

02

Agent 产品责任人

维护 Agent 的工作说明、边界、工具、知识、评估、版本和成本，分析用户编辑、拒绝和例外，并决定改进或退役。

03

数据与知识责任人

负责数据定义、质量、权限、敏感度、来源和保留，确保结构化与非结构化知识都可以被解释、更新和撤回。

04

风险与平台责任人

定义身份、权限、网络、DLP、安全、可观察、成本和发布标准，监测越权、漂移、重复 Agent 和不可解释的自治行为。

每个 Agent 作为持续运营的数字角色管理，而不是一次性交付的软件功能。没有业务责任人、评估集和退役条件的 Agent 不进入生产。

  1. 1 · 提案

    说明对应业务周期、痛点、预期结果、为什么规则或现有 Agent 不足，以及不做什么。

  2. 2 · 设计

    定义工作说明、输入输出、工具、知识、身份、自治级别、确认点、升级、成本和失败路径。

  3. 3 · 评估

    使用真实任务、边界案例、越权尝试和对抗输入评估质量、任务完成、工具选择、安全、延迟和成本。

  4. 4 · 发布

    以小范围用户、低自治级别和清晰回滚开始，逐步扩大对象、工具和自动执行范围。

  5. 5 · 运营与退役

    持续监测结果、编辑、拒绝、例外、成本和风险；当价值消失、能力重叠或责任不清时合并或退役。

15 / 企业路线图

从一个灯塔业务周期起步，同时建设可复用的平台与治理基础

企业路线图不应以 Agent 数量为目标，而应以周期结果和复用能力为目标。首个灯塔项目需要跨部门、有可测量基线、能在 90–120 天验证，并能够沉淀身份、知识、工具、评估和运营模式供下一周期复用。

  1. 阶段 1 · 选择周期与建立基线

    选择一个高价值、跨职能、痛点明确且数据可获得的业务周期，绘制客户结果、等待、交接、返工和责任，建立业务与守护指标。

  2. 阶段 2 · 重构人与 Agent 的工作

    重新排序步骤，删除无价值交接，明确规则、分析模型、Agent 和人的最佳分工，设计确认、升级和失败路径。

  3. 阶段 3 · 交付灯塔周期

    使用真实用户和业务数据分阶段上线，从建议与草稿开始，完成评估、观察和控制后再提高自治；按同一口径比较周期结果。

  4. 阶段 4 · 平台化复用与扩展

    将验证通过的身份、工具、知识、提示、评估、界面和治理模式纳入目录，扩展到相邻周期，合并重复 Agent，并持续跟踪单位结果成本。

标准通过条件不通过时
业务价值直接关联增长、客户结果、周期速度、服务质量或重大风险退回单点效率工具，不作为战略灯塔
跨周期断点存在明显等待、交接、返工、信息丢失或责任空白优先使用局部流程优化
Agent 适配度需要开放语境理解、跨系统协调、动态适应或个性化优先规则、自动化或分析模型
可测量与可控有基线、责任人、数据、评估集、回滚和风险边界先补齐基础，不进入生产试点
复用潜力能沉淀至少两类可供相邻周期复用的能力重新评估平台化投入范围
高级管理层的三项决策 一，批准以业务周期而非应用模块作为 CRM 转型单位；二，选定一个灯塔周期与业务责任人，并授权跨职能团队重构流程；三，批准 BizApps、Modern Work 与 Azure 的分层平台原则，以及 Agent 身份、自治、评估、成本和退役治理。
